# ECGAgent v42 改进与验证

本次修改针对 agent 编排、证据上下文、模型请求和评估，不改动诊断阈值。协议版本升为 `ecgagent.diagnostic.v42`，证据视图版本升为 v5，旧诊断缓存不会作为新协议结果直接复用。

## 已实现

1. **显式阶段控制。** Qwen、DeepSeek 根据调用参数 `phase` 控制 thinking，不再搜索历史里的 `COMPACT PLAN`。Qwen 默认最多使用768个 thinking token，且不超过本次输出预算的三分之一；可以通过 backend 构造参数调整或设为 `None`。有效配置进入审计。
2. **统一默认入口。** Python 构造函数、快捷函数、CLI 和 batch 均默认 compact。旧五阶段测试显式选择 legacy，保留兼容性。
3. **候选与跨域检查。** 有候选时也执行 `review_tools`，为最多两个实际检查视图预留预算。候选分配考虑重要性、尚未覆盖的领域、可用测量支持和新增视图成本；诊断结论不使用这个分数。概览增加有限的 ST/T、Q波和电压测量极值，仍需详细证据判断形态。
4. **节点证据覆盖。** 模型节点与具体工具参数绑定，定义最小显示证据组合。先放入这些组合，再分配可选证据；缺失或压缩掉的必要证据使模型节点保持 unknown。显示下限不等于充分诊断标准。程序节点继续使用完整测量数据。
5. **压缩性能。** Qwen、DeepSeek 和 MedGemma 复用增量计数的证据打包器，减少重复 JSON 序列化和重复元数据。MedGemma 对原子证据 JSON 保持完整单元，避免从中间切断。
6. **局部修复。** compact 的 JSON 解析、结构或输出截断问题允许一次原阶段修复，复用已经获取的证据。截断时只扩大该阶段输出预算。`max_revisions` 仍用于 legacy 的最终修订，不触发无止境临床重判。
7. **缺失与执行错误分离。** 工具明确返回 `measurement_unavailable` 时，表示合法查询已执行但无数据；不获得证据授权，也不把未知节点变成阳性。错误参数、未知工具、预算拒绝和运行异常仍不能满足取证要求。
8. **共享截止时间。** HTTP 请求、可重试错误和整条记录的重跑共享剩余时间。MedGemma 队列等待可超时，过期队列项不再送入推理；已在执行的同步 GPU 内核不能通过此接口强制中断。
9. **完整评估与性能记录。** 新增全队列直接标签指标，将缺失、过期、失败和未验证结果作为弃权；原成功子集指标另行保留。新增候选阶段覆盖、证据可见率、局部修复、逐阶段模型耗时、token、批次实际吞吐和并发度。重建分析 manifest 时保留运行性能数据。
10. **维护性。** 删除没有调用者的旧 `_expand_compact_verdict_v2` 和 `_normalize_verdict_v2`，更新三种语言的入口说明，并增加 `ecgagent.performance` 离线比较命令。

## 验证结果

- 510项 agent、证据契约、诊断对齐、Web 安全及批量诊断相关测试通过；新增测试覆盖阶段开关、局部重试、候选选择、跨域检查、证据组合、缺失数据、HTTP重试及全队列评估。
- `compileall` 与修改差异检查通过。
- 同一合成打包基准：15个视图，每个48条证据，预算8,000字符，重复20次取中位数。旧实现约 **51.758 ms**，新实现约 **3.006 ms**；保留证据从 **32条增至52条**。这是打包器的局部基准，不是模型端到端提速倍数。
- 使用本地 Qwen 权重、vLLM 0.24.0、单张 A100 80GB 和合成特征完成真实推理验证。最终两阶段各调用模型一次，thinking 为 `[false, true]`，裁决 thinking 预算768；`ok=true`、`verified=true`。总耗时约96.9秒，总token为7,767。
- 该合成输入刻意缺少部分模态，最终没有确认诊断；验证的是缺失信息时正确保留不确定性，以及引用、结构和数值边界，不是临床准确率。临时本机推理服务已关闭，GPU显存已释放。

机器可读记录见 [ecgagent_v42_validation.json](ecgagent_v42_validation.json)。真实推理的首次无 thinking 上限尝试发生请求超时；加入上限后才继续完成边界修正和最终验证。不同尝试的候选不完全相同，不能把这几次运行用作配对准确率或端到端提速结论。

## 后续数据实验

使用同一输入队列，在独立输出目录分别运行不同并发度，比较完整队列指标与P95耗时，再决定运行配置。不要以成功记录子集F1替代全队列指标，也不要将候选覆盖率当成诊断精度。

```bash
.venv/bin/python -m ecgagent.performance output_workers1 output_workers2 output_workers4 \
  --output performance_comparison.json
```

该命令只比较已有记录，不发送模型请求。历史产物缺少的逐请求统计保留为不可用。
