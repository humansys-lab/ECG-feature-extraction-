<a id="a-房扑漏检引发的连锁假阳性-优先处理"></a>
## A. Cascading False Positives from Missed Atrial Flutter — Priority Handling

<a id="a0-现象"></a>
### A.0 Phenomenon

Of the 5 reference-annotated records in `Atrial Flutter`, **only 1** (JS01040) generated an atrial flutter statement.
More seriously, the missed detection did not just result in "one missing diagnosis," but **generated incorrect diagnoses**:

| Record | Reference contains AF | Our Output |
|---|---|---|
| JS00956 | Yes | `left_atrial_abnormality` + `first_degree_av_delay` |
| JS00970 | Yes | `left_atrial_abnormality` + `first_degree_av_delay` |
| JS00987 | Yes | `first_degree_av_delay` |
| JS01019 | Yes | (Neither PR nor LAE established, no cascading error) |
| JS01040 | Yes | `possible_atrial_flutter_pattern` ✅ Guard worked correctly |

Quantified consequences:

- `first_degree_av_delay` triggered 5 times in the full batch, **3 times on atrial flutter records** (Reference positive 0, i.e., 5 FP)
- `left_atrial_abnormality` triggered 7 times in the full batch, **2 times on atrial flutter records** (TP 0, FP 7)

The mechanism is clear: **F-waves were mistaken for P-waves**. The F-wave immediately preceding QRS was measured as "P", causing
PR to be measured as prolonged → First-degree AVB; the continuous undulation of F-waves was measured as a wide and deep terminal negative component in V1 → Left Atrial Abnormality.
JS00956's `v1_terminal_p_duration_ms = 94 ms` and JS00970's `92 ms`——
The **total duration** of normal P-waves is less than 120 ms; it is physiologically impossible for the terminal negative portion alone to occupy 90 ms.

<a id="a1-守卫不对称待办成本小先做这个"></a>
### A.1 Asymmetric Guards (To-do, Low Cost, **Do this first**)

**Problem**: Downstream guards only activate when atrial flutter is **confirmed**, treating "atrial flutter detection unavailable" and "atrial flutter absent" as the same thing.

- `clinical_rules/hypertrophy.py: _adult_atrial()` decides whether to
  return `not_applicable` based on `af_afl.probable_flutter`
- `clinical_rules/av_block.py: evaluate_advanced_av_block()`'s `invalid_by` follows the same logic

In testing, the `atrial_flutter_pattern` status for 4/5 atrial flutter records was **`unavailable`** (not `not_matched`),
so the guards did not trigger at all; on the only confirmed case, JS01040, the guards worked very well
(`atrial_morphology_invalid_by: atrial_flutter_pattern` is visible in the evidence).

**Fix**: Change the guard condition from "atrial flutter established" to "**atrial flutter excluded**". When atrial flutter/fibrillation detection itself
is `unavailable`, rules relying on P-wave morphology (LAE, RAE, PR/First-degree AVB) should be downgraded to
`unavailable` or `coverage=partial` + low confidence, rather than issuing definitive conclusions as usual.

**Involved**: `hypertrophy.py:_adult_atrial`, `av_block.py`, `intervals.py:classify_adult_pr`
(The latter already has `atrial_association_unreliable` parameters; it may only require connecting `flutter-unavailable` to this entry point).

**Acceptance**: JS00956/JS00970/JS00987 no longer output `first_degree_av_delay` and
`left_atrial_abnormality`; JS01040 behavior remains unchanged; no regression in full testing.

**Risk**: This will downgrade some originally correct LAE / First-degree AVB cases to unavailable. The area of downgrade needs to be statistically analyzed;
if too large, change to downgrading only within narrower suspicion intervals such as "atrial rate > 200 bpm or regular RR with heart rate 140–160".

<a id="a2-f-波形态特征不可用阻塞成本大"></a>
### A.2 F-wave Morphological Features Unavailable (Blocking, High Cost)

All 4 missing inputs were `rhythm.multilead_F_wave_morphology`, with 2 also missing
`rhythm.validated_qrst_subtraction`. Consequently, atrial flutter detection never ran; it wasn't that it ran and failed to match.

See `docs/诊断特征缺口登记.md` §4.4 —— `atrial.py` already has a QRST template residual pathway,
but it currently only feeds **spectral** analysis of f/F waves, without producing **lead-by-lead F-wave morphology** (sawtooth morphology,
polarity consistency of negative II/III/aVF vs positive V1). This is the true bottleneck for this item.

**Note**: After fixing A.1, these 4 records will no longer produce incorrect diagnoses, but they will still miss the atrial flutter itself.
A.1 is the hemostasis; A.2 is the cure.

<a id="a3-v1-终末-p-时限缺生理上限待办成本小独立兜底"></a>
### A.3 V1 Terminal P Duration Lacks Physiological Upper Limit (To-do, Low Cost, Independent Fallback)

Even without solving atrial flutter detection, `left_atrial_abnormality` should not accept a terminal negative component of 92–94 ms.

**Fix**: Add an upper limit to the LAE criteria in `hypertrophy.py:_adult_atrial`
(Terminal negative duration must not exceed total P-wave duration, and total P-wave duration must be within physiological range);
exceeding this renders the measurement unreliable → `unavailable`. Place thresholds in
`IntervalThresholds` (`p_duration_prolonged_ms = 120.0` already exists for reference).

**Value**: This item is independent of A.1; either one can block these two false positives; doing both is more robust.

## B. LAFB Axis Window and Missing Morphological Criteria

<a id="b0-现象"></a>
### B.0 Phenomenon

Among 99 cases, **LAFB matched 0 times**. Only 1 case had an electrical axis ≤ −45° (the current lower bound of the window), and it failed the morphological criteria;
Additionally, 3 cases fell between −45° and −30°, with 3 labeled as `Axis left shift` in the reference labels.

<a id="b1-现状与文档的差距"></a>
### B.1 Gap Between Current Status and Documentation

`clinical_rules/conduction.py: _lafb()` currently checks only three criteria: electrical axis −90° to −45°, qR pattern in aVL,
and rS pattern in II/III/aVF. Compared to the six criteria in Section 5.4 of the documentation, the following are missing:

| Missing Criterion | Feature Availability | Cost |
|---|---|---|
| **S(III) > S(II)** | ✅ Rule already retrieves `s_amp_mv`(II,III) | Add one comparison line |
| **R(aVL) > R(I)** | ⚠️ Need to add `"I": ("r_amp_mv",)` in `needed` | Add two lines |
| QRS < 0.12 s | ✅ `global.qrs_ms` | Add one line |
| VAT(aVL) ≥ 0.045 s | ❌ **`vat_ms` not exported** | Blocked, see Gap Registration §2.3-2 |

<a id="b2-为什么这三条必须打包做待决策"></a>
### B.2 Why These Three Must Be Bundled (Pending Decision)

Relaxing the electrical axis to −30° **increases recall**, while adding morphological criteria **buys back the specificity lost thereby**; the two cannot be separated.

The −30° to −45° range is the interval with the most diverse causes of left axis deviation (Documentation Appendix B.3: old inferior MI, left ventricular hypertrophy, horizontal heart,
primum ASD, hyperkalemia, pacing), and the existing "inferior rS + aVL qR" is a **qualitative** criterion,
which cannot filter these out—a horizontal heart's left axis deviation also satisfies it.

Those two inequalities are **vector consistency checks**. The terminal vector of LAFB points to the upper left at approximately −60°, projecting onto the lead axes as follows:

| Lead | Lead Axis | Angle with −60° | Projection Coefficient |
|---|---|---|---|
| III | +120° | 180° | **−1.00** |
| II | +60° | 120° | −0.50 |
| aVL | −30° | 30° | **+0.87** |
| I | 0° | 60° | +0.50 |

Therefore, true LAFB must have a deeper S(III) than S(II) and a higher R(aVL) than R(I). In contrast, the main vector of left ventricular hypertrophy/horizontal heart is closer to
−15° to −30° (more purely leftward rather than upward), so the projection on Lead I catches up to or exceeds aVL, and `R(aVL) > R(I)` does not hold.

**Pending Decision**: Whether to relax to −30°. If relaxed, the first three items in B.1 must be implemented simultaneously; if not relaxed, only the first three items are implemented
(improving specificity, recall unchanged). It is recommended to first add the criteria without relaxing, run a cycle to see if the 0 hits change, and then decide.

## C. Sinus Criteria Failure at High Heart Rates (Blocked)

Only 1 out of 10 reference `Sinus Tachycardia` cases was hit. Checking `sinus_mechanism` evidence case by case:
For 8/10 cases, `organized_p_ratio` was only 0.05–0.53 at 100–140 bpm (criterion requires ≥ 0.70),
while the P-axis itself was mostly normal (0–75°).

**This is a degradation of P-wave detection capability at high heart rates, not a threshold set too strictly**—it is exactly the
T-P fusion described in Documentation 18.1. Lowering 0.70 would only let false positives in, **do not make this change**.

See `docs/诊断特征缺口登记.md` §4.4 for the complete data table and required features.

<a id="e-rs-移行区振幅下限未针对低电压标定待办"></a>
## E. R/S Transition Zone Amplitude Lower Limit Not Calibrated for Low Voltage (To-Do)

`MorphologyThresholds.transition_min_r_mv = 0.10` was introduced to fix false positives in the transition zone
(background in Gap Registration §4.3). This value is empirical and **not calibrated for low-voltage records**:
For records with all precordial QRS < 1.0 mV, an absolute lower limit of 0.10 mV may be too high, causing true transitions to be missed.

**Fix**: Change to an adaptive lower limit relative to the precordial voltage scale of the record
(e.g., `max(0.05, 0.08 × 胸导 QRS 峰峰值中位数)`). The required features (per-lead QRS peak-to-peak) already exist.

**Acceptance**: Records where `low_qrs_voltage_precordial_leads` co-occurs with transition zone statements must be manually reviewed to ensure no degradation.

<a id="一个差点引入的缺陷"></a>
### A Near-Introduced Defect

The initial version included "QRS < 120 ms" in the matching criteria for LAFB/LPFB. This would **make double bundle branch block impossible to trigger** —
QRS for RBBB + LAFB is necessarily ≥ 120 ms, with width originating from RBBB. The textbook restriction applies to **isolated** bundle branch blocks.
It has been changed to only record into evidence (`qrs_within_isolated_fascicular_limit`), with wide QRS cases handled by existing LBBB suppression logic. Existing test `test_lbbb_suppresses_fascicular_block_from_same_wide_qrs` caught this error.

<a id="a2-已证伪f-波形态描述符不具鉴别力"></a>
## A.2 Disproved: F Wave Morphology Descriptors Lack Discriminatory Power

Implemented `atrial._flutter_wave_morphology()`, calculating sawtooth asymmetry (amplitude skewness + slope skewness), continuity (proportion of time deviating from baseline), and polarity from existing QRST residuals, and performing cross-lead polarity opposition tests
(inferior negative vs V1 positive). **No discrimination in practice**:

| Record | Reference | Morphology Score |
|---|---|---:|
| JS01040 | Atrial Flutter (confirmed) | 0.69 |
| JS00970 | Atrial Flutter | 0.68 |
| JS00948 | Sinus Bradycardia | 0.64 |
| JS00952 | Sinus Rhythm | 0.65 |
| JS01003 | Sinus Rhythm | 0.62 |

Sinus records 0.62–0.65 vs Atrial Flutter 0.68–0.69, no separation. The reason is that residuals inherently contain uneliminated P/T energy, so any ECG residual has a "periodic shape".

**The real bottleneck lies elsewhere**: `flutter_multilead_consensus` (spectral voting) is False for 4 out of 5 atrial flutter cases. The missing piece is not morphology, but **spectral detection sensitivity**.

Handling: Descriptors are **retained and exported as evidence** (for future work and as evidence for this conclusion), but
**not connected to `F_wave_morphology_validated` gating** — connecting non-discriminatory signals into the clinical decision path is worse than not connecting them.

> Note: Protection in A.1 **does not depend** on A.2. A.1 uses "whether organized atrial activity exists",
> so whether atrial flutter is detected or not does not affect its ability to stop false positives.

<a id="c-已回退朴素修法以房扑安全性换窦速召回"></a>
## C Reverted: Naive Fix Traded Atrial Flutter Safety for Sinus Tachycardia Recall

The root cause is more precise than originally recorded. **P waves were not missed** — 47 atrial events detected from 21 beats.
The problem lies in the **classification** of `atrial._associate_event_to_qrs()`:

| Record | Beats | Events | conducted | retrograde | blocked |
|---|---:|---:|---:|---:|---:|
| JS00960 | 21 | 47 | **2** | 19 | 26 |
| JS00966 | 22 | 48 | **1** | 21 | 26 |
| JS01008 | 21 | 49 | **2** | 19 | 28 |

`retrograde` count is almost exactly equal to the beat count — **one event per beat was classified as retrograde**. Sinus tachycardia should have no retrograde P waves.

Mechanism: After RR shortening, the conducted window (60–280 ms before QRS start) and retrograde window (0–240 ms after QRS end)
can accept the same deflection simultaneously, and the sorting key is `(|dt|, priority)` — winning by distance, `priority`
(conducted=0 / retrograde=1) never gets to take effect.

Changing to `(priority, |dt|)` indeed significantly improved the sinus tachycardia side:

| Record | Before | After |
|---|---:|---:|
| JS00960 | 0.10 | **0.90** |
| JS00966 | 0.05 | **1.00** |
| JS01008 | 0.10 | **0.71** |

**But simultaneously regressed atrial flutter**: `organized_p_ratio` for JS01040 (confirmed atrial flutter) went from **0.05 → 0.84**,
meaning F waves were read as conducted P waves. Consequences are twofold: ① Directly breached A.1's 0.35 guard, bringing back the LAE / 1st-degree AVB false positives just fixed; ② Atrial flutter might be reported as sinus rhythm. Furthermore, existing test
`test_associate_event_prefers_closest_boundary_in_overlap_window` explicitly locked "winning by distance"
as an intentional design.

Trading atrial flutter safety for recall of 3 out of 9 sinus tachycardia cases is a loss, so **reverted**, with code comments explaining why this change cannot be made.

**The correct fix requires evidence beyond distance**: PR intervals for sinus conducted P waves are **stable** across beats, whereas "PR" intervals from F waves accidentally falling into the conducted window are unstable. Using beat-to-beat PR clustering stability as the arbiter for conducted/retrograde,
the required data (`atrial_events` already includes `pr_ms` and `associated_qrs_beat_id`) is available, making this the clear next step.

<a id="剩余工作"></a>
## Remaining Work

Items 1–5 in the original execution order are complete. The remaining two items both boil down to **the same body of work**:
detection and attribution of atrial activity, not the rule layer.

1. **Correct fix for C**: Use beat-to-beat PR clustering stability to arbitrate conducted / retrograde, replacing the current pure distance criterion.
   Data is available (`atrial_events` includes `pr_ms` + `associated_qrs_beat_id`), requiring a supporting atrial flutter regression set
   to prevent "saving sinus tachycardia but hurting atrial flutter" again.
2. **Correct fix for A.2**: Improve **spectral** atrial flutter detection sensitivity (`_spectral_flutter_analysis`),
   rather than adding morphology items. Morphology descriptors have been exported and can serve as secondary confirmation after sensitivity improvement, but are unsuitable for standalone gating.

Both items require a larger annotated dataset with sufficient atrial flutter/tachycardia cases than 100 records to safely tune parameters. It is recommended to expand data before modifying code.
