# 統合臨床 ECG ルール設計

日付: 2026-07-12

<a id="1-objective"></a>
## 1. 目的

ECG 機能に権威ある臨床解釈レイヤーを 1 つ導入します
抽出器。公的臨床基準は診断動作を定義します。既存の
Glasgow および Philips/DXL からインスピレーションを得た出力は、追跡可能なリファレンスとして引き続き利用可能です
解釈はありますが、最終的な要約は決定されません。

新しい層では、次のような現在の障害モードを排除する必要があります。

- 診断中に正常な ECG を報告する部分的な Glasgow 実装
  章は保留中です。
- グラスゴーおよび DXL にヒントを得たロジックにより、互換性のない間隔または形態が生成される
  仲裁なしで結論を出す。
- ポジティブルールを満たす測定値が欠落している。
- 軸のみの束状ブロック診断。
- 非連続的または人口統計学的に不正確な ST 上昇の決定。
- 古い生成されたアーティファクトが、ルール変更後に最新のものとして表示されます。

実装は研究システムのままです。エンジニアリングルールの完成
このセットはグラスゴー/フィリップス独自の医療機器認証を主張していません
同等性、または臨床的検証。

<a id="2-confirmed-decisions"></a>
## 2. 確認された決定

1. 公的な AHA/ACC/HRS、ESC、および心筋梗塞の世界的定義
   基準は最終的な臨床声明の権威です。
2. 既存の出力フィールドは互換性のために引き続き使用できます。
3. グラスゴーおよび DXL からインスピレーションを得た結論は参照のみです。
4. 必須の入力が欠落している場合は、`unavailable` または `indeterminate` が生成されます。それはできます
   肯定的な診断も正常性の証拠も生成されません。
5. 実装では、現在の臨床ルール パッケージとともに新しい臨床ルール パッケージを使用します。
   信号処理を書き直すのではなく、特徴抽出器を使用します。
6. 最終解像度コンポーネントの名前は、`ClinicalStatementResolver` です。

<a id="3-architecture"></a>
## 3. アーキテクチャ

データフローは次のとおりです。

```text
ECGFeatureExtractor / ECGFeatures
            |
            v
ClinicalContext adapter
            |
            v
quality -> rhythm -> conduction/intervals -> hypertrophy -> ST/T/MI
            |
            v
ClinicalStatementResolver
            |
            v
clinical_interpretation.v1
            |
            +-> report
            +-> app
            +-> MedGemma
            +-> batch exports
```

新しいパッケージは `feature_extraction/ecgfeat/clinical_rules/` です。

- `models.py`: ルールの仕様、評価、ドメインの結果、競合、
  概要および完全な分析モデル。
- `context.py`: 正規化された患者、測定、信頼性、リードの向き、
  ペーシングと基準結果の事実。
- `quality.py`: 技術的な制限とドメインの可用性。
- `rhythm.py`: 既存のリズム証拠の統合投影。
- `conduction.py`: QRS 幅、BBB、および束状ブロックのルール。
- `intervals.py`: PR および QT の計算と分類。
- `hypertrophy.py`: ECG 電圧基準ステートメント。
- `ischemia.py`: ST 偏差、Q 波、および梗塞パターンのルール。
- `resolver.py`: 抑制、競合、ドメインの完全性、および最終的な概要。
- `engine.py`: 決定論的なオーケストレーション。
- `compatibility.py`: 非破壊的なレガシー アノテーションとプロジェクション。
- `sources.py`: 安定したルール ソース識別子とルール セット バージョン。

ルール評価者はプレゼンテーション テキストや他の評価者のテキストを読むことはできません。
レンダリングされたステートメント。ルールは正規化された事実と事前に構造化されたもののみを使用します
ドメインの結果。

<a id="4-rule-evaluation-contract"></a>
## 4. ルール評価契約

すべてのルール評価には次のものが含まれます。

```json
{
  "rule_id": "CLIN-CONDUCTION-LAFB-01",
  "domain": "conduction",
  "status": "matched",
  "statement_code": "lafb_pattern",
  "statement": "ECG pattern consistent with left anterior fascicular block",
  "severity": "abnormal",
  "confidence": "criteria_met",
  "required_inputs": [],
  "missing_inputs": [],
  "evidence": {},
  "thresholds": {},
  "suppressed_by": [],
  "source": {
    "authority": "AHA/ACC/HRS",
    "document": "Recommendations for Standardization and Interpretation of the ECG, Part III",
    "section": "Fascicular blocks",
    "version": "2009"
  }
}
```

許可される評価ステータスは次のとおりです。

- `matched`
- `not_matched`
- `unavailable`
- `not_applicable`
- `suppressed`

`unavailable` は、必要な測定値が欠落している場合、有限ではない場合に必須です。
信頼性が低い、リードの向きが原因で除外されている、または配線されたものではサポートされていない
患者集団。

<a id="5-domain-behavior"></a>
## 5. ドメインの動作

<a id="51-quality-and-availability"></a>
### 5.1 品質と可用性

品質が第一に評価されます。影響を受ける最小のドメインには制限が適用されます。

- 四肢誘導の逆転により、前頭軸と四肢誘導の形態が制限されます。
- 前胸部の逆転は、前胸部の ST、Q 波、BBB、RVH、および R 進行を制限します
  ルール。
- P 波の信頼性が低いため、心房調律、PR、心房拡大が制限されます。
- QRS の信頼性の低さにより、伝導、Q 波、および肥大ルールが制限されます。
- T/QT の信頼性が低いため、再分極と QT ルールが制限されます。

技術的に制限されたドメインはネガティブなドメインではありません。

<a id="52-rhythm"></a>
### 5.2 リズム

臨床層は、構造化された QRST を差し引いて整理された心房残差を再利用します。
P 波の証拠、RR 変動、ペーシングの状況、早発性コンプレックスの証拠、および
AV 関係の証拠は抽出者によってすでに作成されています。

RR 変動係数のみから AF を推測するわけではありません。 AF/AFL ステートメント
記録期間、心房信号の利用可能性、組織的P比、
RR の証拠、検証ステータス、および信頼性。ペーシングと AV ブロックの制限
依存するリズムステートメントの前に解決されます。

<a id="53-conduction"></a>
### 5.3 伝導

- 非特異的 IVCD には、ガイドライン QRS の期間基準と、
  完全な RBBB/LBBB 形態。
- RBBB と LBBB には、期間と形態の両方の証拠が必要です。
- 不完全な BBB ラベルには、特定の形態と持続期間の範囲が必要です。
- LAFB には、定義された左軸範囲に aVL および rS/inferior-lead の qR を加えたものが必要です
  形態。軸だけでは不十分です。
- LPFB には、右軸範囲に I/aVL の rS と III/aVF の qR を加えたものが必要です。
  右軸偏差の競合する原因が交絡因子として表されます。
- コンポーネントの持続時間または必要な形態が測定されていない場合、関連する
  振幅だけから推測するのではなく、診断を行うことはできません。

ペイロードは、バゼット、フリデリシア、ホッジス、およびフラミンガムの計算を公開します。
成人の最終 QT 分類では、一次補正としてホッジスが使用されます。

Bazett は実質的に 60 bpm 以外のレートでは参照のみであり、独立してはなりません
最後の延長 QT ステートメントを生成します。自動化された QT 延長には以下が含まれます。
手動レビューの勧告。 T 端が次の場合、QT 分類は使用できません。
信頼性が低い、RR の変動により補正が無効になる、または設定されたワイド QRS
ガードが適用されます。

アダルト PR 分類では、短い PR には `<120 ms` が、短い PR には `>200 ms` が使用されます。
第一級AV遅延。小児 PR 分類にはサポートが必要です
年齢別の公開参照表。そのテーブルがエンコードされるまで、小児科

<a id="55-hypertrophy"></a>
### 5.5 肥大

臨床レイヤーは、解剖学的チャンバーではなく、ECG 電圧基準という名前のレポートを作成します。
確定診断としての肥大。 Cornell の電圧/積と Sokolow-Lyon
基準には、性別、年齢、行動、リードの質のコンテキストが保持されます。結果はテキストを使用します

RVH および心房異常のステートメントには、形態および期間の事実が必要です
彼らのルールで指定されています。コンポーネントの継続時間が不足している場合は、合格としてカウントされません。
完全にエンコードされていない小児パーセンタイル ルールは利用できず、
大人のポジティブなルールに戻ります。

<a id="56-st-q-waves-and-infarction-patterns"></a>
### 5.6 ST、Q 波と梗塞パターン

- ST 上昇は、解剖学的に連続したリードの J ポイント測定を使用します。
- V2 ～ V3 の閾値は性別と男性の年齢によって選択されます。他のリードは彼らの
  ガイドラインの閾値。
- すべての寄与するリードは信頼できるものでなければならず、除外されてはなりません。
- ST 低下領域ステートメントでは、連続したリードを使用し、区別します。

- Q 波ルールでは、測定可能な持続時間と該当する振幅が必要です。
  必要なリードのグループ化における Q/R 基準。
- リードの配置エラー、事前励起、BBB、LVH/RVH、およびその他の既知の交絡因子

## 6. ClinicalStatementResolver

リゾルバーは医学的なしきい値を定義しません。これらの制御のみを行います
機能:

1. ドメインが利用できないことを伝達します。
2. 技術的および診断的抑制関係を適用します。
3. 同等のステートメントの重複を排除します。
4. 矛盾する参照結論を矛盾として保持します。
5. 最終的なステートメントと境界線のステートメントをランク付けします。
6. 正規性が必要な領域がすべて完了しているかどうかを判断します。
7. 単一の最終要約を作成します。

許可される全体的な概要は次のとおりです。

- `normal`
- `borderline`
- `abnormal`
- `technically_limited`
- `incomplete`

`normal` は、正規性が必要なドメインがすべて評価された場合にのみ許可されます。
品質は十分であり、一致する異常/境界線のステートメントは存在せず、
重要な必須入力が欠落しています。保留中または未実装のルール ファミリが強制的に適用される
`incomplete`。

<a id="7-output-contract"></a>
## 7. 出力コントラクト

完全な輸出により次のメリットが得られます。

```json
{
  "clinical_interpretation": {
    "schema_version": "clinical_rules.v1",
    "ruleset_version": "2026.07.1",
    "artifact_fingerprint": "sha256:4c4518b2-example",
    "generated_at": "2026-07-12T12:00:00Z",
    "overall_status": "incomplete",
    "summary": {},
    "final_statements": [],
    "borderline_statements": [],
    "suppressed_statements": [],
    "unavailable_domains": [],
    "conflicts": [],
    "domains": {},
    "reference_interpretations": {
      "glasgow": {},
      "dxl": {}
    }
  }
}
```

既存の `interpretation`、`glasgow`、および `statement_engine` 構造は残ります。
トップレベルのエクスポート メタデータにより、次のメリットが得られます。

```json
{
  "reference_only": true,
  "superseded_by": "clinical_interpretation"
}
```

互換性の追加は非破壊的です。既存のキーと値の型は
削除または名前変更されていません。

<a id="8-presentation-and-consumers"></a>
## 8. プレゼンテーションと消費者

- テキストと画像のレポートでは、最初に統一された概要が表示されます。
- Glasgow および DXL からインスピレーションを得た結果は、参照アルゴリズムの付録に移動します。
- アプリと MedGemma コンテキストは、権限のあるものとして `clinical_interpretation` を使用します
  結果と参照の競合を個別に説明します。
- バッチ エクスポートには、統合されたフィールドとルールセットのバージョンが含まれます。
- レポートのレンダリングでは、埋め込まれたフィンガープリントと現在のペイロードが比較されます。
  不一致があると `STALE ARTIFACT` が表示され、アーティファクトが生成されなくなります。
  現在のものとして提示されています。

フィンガープリントはルールセットのバージョン全体にわたって決定的であり、臨床的に正規化されています。
分析とソース機能の識別。 `generated_at` はハッシュから除外されます。

<a id="9-error-handling"></a>
## 9. エラー処理

- 単一のルール例外は、エラー コードとともに利用できない評価になります。
  消えません。
- 正規性が要求されるルールに違反すると、不完全な要約が強制されます。
- 非有限の測定値は欠損として扱われます。
- 不明な性別、不十分な年齢精度、サポートされていないリード、および臨床症状の欠如
  コンテキストが明示的に表現されます。
- 厳密モードでは、開発およびテストで評価エラーが発生します。通常のランタイム
  それらを分析に記録します。

<a id="10-testing-and-acceptance"></a>
## 10. テストと承認

<a id="101-rule-boundaries"></a>
### 10.1 ルールの境界

各しきい値には、以下/等しい/以上のテストがあります。テストは連続リードロジックをカバーします。
年齢と性別のルート、品質ゲート、交絡因子、欠落している入力。

<a id="102-resolver-invariants"></a>
### 10.2 リゾルバーの不変条件

- 必要な証拠が入手できない場合、一致するルールを作成することはできません。
- 正規性が必要なドメインが欠落していると、`normal` が禁止されます。
- 参照アルゴリズムは、統一された最終要約を変更することはできません。
- 前胸部の逆転は、依存的な前胸部の診断を抑制します。
- LBBB/ペーシングは専用の虚血パスを使用します。
- 競合は表示されたままになります。

<a id="103-end-to-end-regression"></a>
### 10.3 エンドツーエンドの回帰

JS00059 は生のレコードから再処理されます。新しい JSON とレポートは次のとおりであってはなりません
QT分類、前胸部逆転、
RVH および後部 MI 出力。従来のフィールドは引き続き読み取り可能です。

追加のフィクスチャは AF、AFL、ペーシング、AV ブロック、RBBB、LBBB、筋膜をカバーします
ブロック、WPW、ST上昇パターン、事後パターン、Q波、LVH電圧、
低電圧と小児の境界。

<a id="104-clinical-validation-interface"></a>
### 10.4 臨床検証インターフェース

リポジトリには、感度、特異度、PPV、
診断、年齢、性別、信号品質層別の NPV と F1。単体テストはそうではありません
臨床検証として提示されています。研究用途のラベルは、
独立した臨床医の判断による検証は、個別に承認された目標を満たします。

<a id="105-engineering-acceptance"></a>
### 10.5 エンジニアリングの承認

- すべての新しいルール テストに合格します。
- 現在実行可能なレガシー スイートでは新たな障害は発生しません。
- アプリ、MedGemma およびバッチ消費者契約テストに合格。
- 再生成されたすべての JS00059 アーティファクトは、1 つのルールセットのバージョンとフィンガープリントを共有します。
- レポートおよび JSON 出力は、参照のみのアルゴリズムを明確に識別します。
- 不完全または未実装のドメインでは、通常の概要は生成されません。

<a id="11-delivery-sequence"></a>
## 11. 配信シーケンス

1. モデル、ソース、コンテキスト、およびリゾルバーの不変条件。
2. 品質とドメイン完全性の動作。
3. QT と伝導の補正。
4. ST/Q 波/虚血ルールと Sgarbossa パス。
5. 肥大および小児の利用可能性に関するポリシー。
6. 輸出の互換性と消費者の移行。
7. アーティファクトのフィンガープリントとレポートの再生成。
8. 検証ユーティリティと完全な検証。

<a id="12-non-claims"></a>
## 12. ノンクレーム

この著作物は次のことを主張しません。

- 独自のグラスゴーまたはフィリップスのアルゴリズムを正確に再現。
- 心臓専門医の検査に代わる;
- ECG 単独による急性心筋梗塞の診断。
- 医療機器認証;
- 臨床精度は単体テストに合格することによってのみ得られます。
