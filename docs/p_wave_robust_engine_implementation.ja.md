# P-wave の堅牢な区切りエンジンの実装と検証監査

生成時間: 2026-07-28

<a id="结论"></a>
## 結論

`docs/p wave doc.md` で必要な決定論的 DSP 変換の最初のラウンドは、`ecgfeat` メイン プロセスに統合されました。
新しい実装では、単一のコンセンサス境界を無条件に有効な結果として扱うことはなくなりましたが、同時にリードバイリードの証拠を導き出します。
厳格/堅牢な境界、エクスペリエンスCI、Pステータス、コレクションチェーンの品質管理、構造化された拒否理由。

200 LUDB レコードの凍結された v3 エージェント評価では、完全な P 境界カバレッジが維持されます。
93.3%。 Ta/TPガード、ビートレベルのオンセット、オフセット、Pタイムリミットのバイアスの前バージョンと比較して、
SD、MAE、および P95 絶対エラーはすべて改善されています。レコードレベル P のタイミング平均差は -15.03 ミリ秒から
-8.52ミリ秒。

これはまだ正式な IEC/CSE 準拠の結論ではありません。 LUDB は開発とパラメータ凍結の両方に参加し、CI を経験しました
外部データベースでまだ調整されていません。厳密に言えば、8 つの偏差を除外した後のレコードレベルの平均差は -10.05 ミリ秒です。
プロキシ制限の ±10 ミリ秒よりもまだ 0.05 ミリ秒長いです。

<a id="实现范围"></a>
## 実装範囲

<a id="采集链和同步"></a>
### 収集チェーンと同期

`feature_extraction/ecgfeat/acquisition_qc.py` を追加しました:

- QRS 導関数エンベロープを使用してリードごとの固定遅延を推定し、サブサンプリング放物線改良をサポートします。
- 遅延のみ 8 ～ 20 ミリ秒、ビート間 MAD は 2.5 ミリ秒以下、補正された相関係数は 2.5 ミリ秒以上
  0.75 であり、自動的に補正される前の関連する改善は少なくとも 0.08 です。
- 補正後に QRS を再検出します。ビート番号が変更されるか、QRS P95 変位が 12 ミリ秒を超えると、完全にロールバックされます。
- 重複チャンネル、グループ内の異常なゲイン、フィルタリングの不一致、重大な四肢誘導設定エラーを確認します。
- 安全に補償できない明らかな非同期は、`CHANNEL_DESYNCHRONIZED` との権限のある融合をブロックします。

<a id="基线检测和空间处理"></a>
### ベースライン、検出、空間処理

`feature_extraction/ecgfeat/p_wave_engine.py` を追加しました:

- P/QRS/T が除外され、活性が低いサンプルから静かな観察マスクを構築します。
- 共通ドリフトとリードごとの残差の決定論的カルマン状態空間モデルを使用してベースラインを推定します。
- 将来の情報漏洩を防ぐために、オフラインでは前方/後方平滑化が使用され、オンラインでは前方状態のみが使用されます。
- プレシジョンブランチはより広い帯域幅を維持します。検出ブランチは 35 Hz ローパスを使用します。
- 静かなサンプルからノイズ共分散を推定し、マルチリード微分アクティビティをホワイトニングします。
- 粗い P ウィンドウ内の特異値によってスケーリングされた 1 次元または 2 次元の空間表現を選択します。
- 検証可能な静かなサンプルがない場合にローカル SNR を偽らないで、ベースラインの信頼性を明示的に下げます。

<a id="p-on-tt-重建和-ta"></a>
### P-on-T、T 再構成と Ta

- T 再構成は、同様の RR を持つ他のショットからのみ学習し、ソース ショットとターゲット ショットのすべての P 領域をマスクします。
- テンプレート フィッティングでは、±8 ms の変位、0.97/1.00/1.03 のストレッチ、および制限されたロバストなアフィン変換のみが許可されます。
- 減算エッジにはコサイン テーパーを使用します。残留エネルギーと 2 次微分高周波比を検証する必要があります。
- 元の信号、検証された T 再構成残差、および T 空間部分空間抑制ブランチを並行して保存します。
- T 再構築が失敗した場合、分岐間で一貫性がない場合、または Ta オフセットが認識できない場合、信頼性を下げるか判断を拒否します。
  「残留物がきれいになった」ということを受け入れの根拠として受け入れないでください。

<a id="逐导联边界和不确定度"></a>
### リードごとの境界と不確実性

各候補は同時に実行されます。

- 4%、6%、8%、10%、12%の振幅ヒステリシス
- マルチスケール導関数/DoG アクティブ境界
- 最小二乗接線
- 地域のエネルギー変化点
- 非Taシナリオにおける条件付きエリア境界
- 正および負のベースライン不確実性の摂動

出力 `PWaveLeadBoundary` (オンセット/ピーク/オフセット、両端の CI、シグマ、独立信頼度を含む)
ローカル SNR、品質スコア、ベースライン パターン、T 再構成ステータス、Ta/P-on-T フラグ、分岐の違い、
使用方法とフラグ。等電性、高ノイズ、またはハード QC に合格しないリードは、権威融着に入りません。

<a id="多导联融合和拒判"></a>
### 複数リードの融合と拒絶

- 候補クラスターは固定アンカーを使用し、シングルチェーンは禁止されています。
- onset は最も古い適格なクラスターを選択し、offset は最新の適格なクラスターを選択します。
- 少なくとも 3 つの有効なリードと 2 つの独立したグループが必要です: 四肢、右前胸部、
  記録されたままです。
- 各リードの重みには上限があり、投票の繰り返しのカウントを避けるために、関連する各リード グループの合計重みには再び上限が設けられます。
- 厳格な品質管理の後、厳密な境界は最も早い開始/最も遅いオフセットを保持します。堅牢な境界はグループ権限を使用します
  フラクショナルフュージョン。
- 新しいロバスト モデルと既存のコンセンサス モデルは、2 つの独立したモデルとして相互に確認します。既存のモデルには完全な境界がありません
  、新しい候補者は監査のために予約されていますが、`MODEL_DISAGREEMENT` で拒否されます。
- オンセットは 2 つのモデルに同じ重みを与えます。オフセットは遅延保存フュージョンを使用し、それ以降のモデルの重みを使用します。
  証明された P 時間制限全身性収縮の阻害については 87.5%。

各ビートは `PWaveBeatAssessment` を出力します。ステータスは次のとおりです。

- `P_PRESENT`
- `AF_LIKE`
- `ORGANIZED_ATRIAL_ACTIVITY`
- `OVERLAP_UNCERTAIN`

サポートされている拒否の理由は次のとおりです。

- `BASELINE_UNOBSERVABLE`
- `P_ON_T_UNRESOLVED`
- `P_OFFSET_TA_AMBIGUOUS`
- `INSUFFICIENT_INFORMATIVE_LEADS`
- `CROSS_LEAD_DISAGREEMENT`
- `CHANNEL_DESYNCHRONIZED`
- `LEAD_CONFIGURATION_INVALID`
- `MODEL_DISAGREEMENT`

<a id="拍间一致性与接口"></a>
### ビート間の一貫性とインターフェイス

- R ポイントを基準としたオンセット/オフセット形状ベクトルに基づいて、決定論的なビート間クラスターを確立します。
- 異所性ビートをマスクする可能性のある境界での時間的平滑化を行わずに、クラスター内ジッターのみを使用して CI を拡張します。
- `ECGFeatures.p_wave_assessments` 完全な新しい契約を保存します。
- `metadata.acquisition_qc` および `metadata.p_wave_contract` は、レコードレベルの監査概要を保存します。
- 構造化エクスポート `provenance` には、取得 QC、P 契約、およびビートごとの評価が含まれます。
- 相互検証に合格した堅牢な境界のみが元に書き戻されます。
  `p_onset_consensus_index`/`p_offset_consensus_index`、ダウンストリーム互換性を維持します。

<a id="尚未关闭的验证缺口"></a>
## まだ埋められていない検証ギャップ

1. 経験的 CI は、閾値、手法、ベースライン、および心拍数の変動からのみ得られ、名目上のカバレッジは完了していません。
   校正済み。出力には `empirical_perturbation_uncalibrated` というラベルが明確に付けられます。
2. LUDB はパラメーターの選択に使用されており、パラメーターをフリーズした後、リードバイリード P アノテーションを持つ 2 番目のデータ セットを使用する必要があります。
   独立した検証を行います。
3. AF/心房粗動、P なし、P-on-T、TP なしの高心拍数、Ta の強い干渉、および低振幅 P は、引き続き個別に報告する必要があります。
   層別受入率、誤検知率、および CI カバレッジ。
4. レコードレベルのトリミングされたバイアスは -10.05 ミリ秒です。エージェント制限を 0.05 ミリ秒超えるだけですが、次のように書き込むことはできません。
   ±10ms経過。
5. 新しいエンジンにより、決定論的なマルチブランチ計算の量が増加します。オンライン遅延を測定することも必要です。
   最悪の実行時間。
