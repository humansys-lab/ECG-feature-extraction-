# P 波のオンセット/オフセット検出問題とコンセンサス強化分析

この記事では、現在の P 波関連の検出、特に `P onset` と `P offset` の大きな偏差の理由と、「各リード、各ビート -> 代表波形 -> 複数リードのコンセンサス」の方法を使用して安定性を高める方法に焦点を当てます。

<a id="1-结论概览"></a>
## 1. 結論の概要

現在のアルゴリズムにはすでに P 波コンセンサス メカニズムの一部が含まれていますが、主に P ピーク候補を固定し、`pr_consensus_ms` を導出するために使用されます。特に `P offset` の真の P 波境界は、依然として主に各リードのローカル タンジェント/しきい値ロジックによって独立して決定されます。

<a id="11-已实现的第一阶段修改"></a>
### 1.1 実装された第 1 段階の変更

このラウンドでは、保守的な実装のバージョンが完成しました。

1. ビートレベル `LeadBeatFeatures` に次のような P 境界コンセンサス バイパス フィールドを追加しました。
   - `p_onset_consensus_index`
   - `p_offset_consensus_index`
   - `p_dur_consensus_ms`
   - `pr_segment_consensus_ms`
   - `p_onset_consensus_support`
   - `p_offset_consensus_support`
   - `p_onset_consensus_spread_ms`
   - `p_offset_consensus_spread_ms`
   - `p_boundary_consensus_source`

2. `_apply_multilead_consensus(...)` は、同じビートの信頼できる P オフセットに対してクラスターのコンセンサスを実行します。
   - 同じオフセット クラスターをサポートするには、少なくとも 3 つの信頼できるリードが必要です。
   - 元の `bf.p.offset` を上書きしません。
   - コンセンサス オフセット、P デュレーション、PR セグメントのみをバイパス フィールドとして記録します。

3. `build_representative_lead_features(...)` は、これらの P コンセンサス境界フィールドを `representative_leads.*.params` に集約します。

4. `compute_global_features(...)` のグローバル PR は、保守的なコンセンサス ゲートを追加します。
   - 生の四肢リード PR は明確に分割する必要があります。
   - サポートされている `pr_consensus_ms` は、少なくとも 3 つのオンセット コンセンサスによってサポートされている必要があります。
   - コンセンサス PR は `120-300 ms` の範囲内である必要があります。
   - コンセンサス PR は、生の四肢中央値より少なくとも 25 ミリ秒長くなければなりません。これは主に、P の遅発性によって引き起こされる短い PR を補正するために使用されます。
   - レコード 57 などの 102ms コンセンサスの悪用を避けるために、短いコンセンサスはグローバル PR を引き継ぎません。

LUDB スポットチェック：

- レコード 39: グローバル PR が `136 ms` から `201 ms` に調整されます。 GT `224 ms`と比較すると、誤差は`-88 ms`から`-23 ms`に改善されています。
- レコード 57: `pr_consensus_ms=102 ms` は引き継がれておらず、グローバル PR は短いコンセンサスの悪用を避けるために生のパスを維持しています。
- レコード 130: `pr_consensus_ms=124 ms` と生の中央値の差が十分でないため、引き継がれません。
- レコード 5: P オフセット コンセンサス / P デュレーション コンセンサス バイパス フィールドが生成されますが、グローバル PR は元の生のパスを維持します。

<a id="12-已实现的第二阶段修改p-onset-cluster-consensus"></a>
### 1.2 第 2 段階の修正の実装: 開始クラスターのコンセンサス

続いて、P onset のクラスターレベルのコンセンサス強化が完了しました。主な目標は、グローバル PR に短い PR の偽のコンセンサスが無条件で使用されることを回避しながら、「QRS に近い偽の P によって生のリードごとの PR が短縮される」という問題を解決することでした。

実装のポイント:

1. `_apply_multilead_consensus(...)` は、すべての P オンセットの単純な P10/中央値を使用しなくなりました。まず、同じ拍動の信頼できるリードの開始時間によってクラスター化されます。
2. 開始クラスターは一般的な制約を満たす必要があります。
   - 少なくとも 3 本の信頼できるリードによってサポートされています。
   - クラスターの広がりは約 `45 ms` を超えません。
   - クラスター PR は、`120-260 ms` の生理学的範囲に位置します。
   - 四肢/前胸部サポート数と参加リードリストを記録します。
3. 適格な生理学的クラスターがある場合、`pr_consensus_ms` はクラスター センターを使用します。それ以外の場合は、元のパーセンタイル パスに戻ります。
4. `build_representative_lead_features(...)` は、`p_onset_cluster_*` メタデータを代表リードに集約します。
5. `compute_global_features(...)` の PR コンセンサス ゲートにより、より狭い救済パスが追加されます。生の PR 分布に明らかな短い PR 外れ値があり、オンセット クラスターに十分なサポート、小さな広がり、および十分な四肢誘導サポートがある場合にのみ、グローバル PR を生の中央値からクラスター コンセンサスに引き上げることが許可されます。

LUDB 外れ値スポットチェック：

- レコード 2: グローバル PR が `170.5 ms` から `178.0 ms` に調整されます。 GT `194.5 ms`と比較すると、誤差は`-24.0 ms`から`-16.5 ms`に改善されています。
- レコード 64: グローバル PR が `127.0 ms` から `143.0 ms` に調整されます。 GT `175.0 ms`と比較すると、誤差は`-48.0 ms`から`-32.0 ms`に改善されています。
- レコード 139: GT `162.0 ms` と比較して、グローバル PR が `206.0 ms` から `199.0 ms` に調整され、誤差が `+44.0 ms` から `+37.0 ms` に改善されます。

<a id="13-已实现的第三阶段修改pr-core-rescue-按-beat-投票"></a>
### 1.3 実装された第 3 フェーズの修正: PR コア レスキュー投票 (ビートごと)

さらに分析を進めると、かつては `_physiologic_pr_core_from_beats(...)` がすべてのリードビート PR 候補者を直接まとめて上位パーセンタイルを獲得していたことが判明しました。これにより、特定のビート上の複数のリードに対して同じタイプの誤って長い PR が繰り返しカウントされるため、グローバル PR が過度に拡張されます。

現在は次のように変更されています。

1. さらに、PR 生理学的範囲、P 信頼度、および `p_unreliable` フラグによって候補をフィルタリングします。
2. `beat_id` に従って最初のグループを作成し、各拍の PR 中央値を取得します。
3. 次に、ビートレベル PR コアで元の中央値/上位パーセンタイルの集計を実行します。

これにより、短い PR の偽候補が多数を占める場合にアッパー コア レスキューを使用する機能が維持されますが、単一の異常なビートに対して複数のリードに繰り返し投票することが回避されます。

LUDB 外れ値スポットチェック：

- レコード 182: グローバル PR が `202.12 ms` から `136.58 ms` に調整されます。 GT `134.0 ms`と比較すると、誤差は`+68.12 ms`から`+2.58 ms`に改善されています。
- レコード 139: グローバル PR は、第 2 段階の `199.0 ms` から `173.68 ms` にさらに調整されます。 GT `162.0 ms`と比較すると、誤差は`+37.0 ms`から`+11.68 ms`に改善されています。
- 12 個の PR 外れ値の小規模バッチ レコードで、PR MAE は、約 `50.47 ms` の第 1 段階の結果から、約 `47.93 ms`、約 `40.40 ms` の第 2 段階の結果に低下しました。

上記の変更では、条件判断にレコード ID、LUDB 注釈、ファイル名、診断ラベル、患者メタデータは使用されません。レコードは回帰検証サンプルとしてのみ使用されます。

<a id="14-已实现的第四阶段修改强共识回写原始-p-wavebounds"></a>
### 1.4 第 4 段階の修正を実装: 強力なコンセンサスが元の P WaveBounds を書き戻す

プロジェクトのルート ディレクトリにある `P wave` 技術文書を参照すると、目的は最終レポートの PR を基準値に近づけることだけではなく、元の P 波境界検出自体の信頼性を高めることであることがさらに明確になります。ドキュメントでは、中央値/代表 P 検出は真の P オンセット/オフセットを出力する必要があり、レポートはこれらの測定値のみを使用する必要があることを強調しています。

したがって、現在の `_apply_multilead_consensus(...)` は、「書き込み専用コンセンサス バイパス フィールド」から「強力なコンセンサスの場合に保守的に修正される生の `WaveBounds`」に拡張されました。

1. 明らかに外れ値の生の `p.onset` の場合:
   - 適格な生理学的発症クラスターが存在する必要があります。
   - 生の開始点とクラスター中心の差は少なくとも約 `20 ms` です。
   - 修正後は `p_onset < p_peak < p_offset` を満たす必要があります。
   - P 持続時間、オンセットからピークまで、および PR セグメントはすべて生理学的範囲内である必要があります。
   - 修正後、生の `pr_ms` と `p_dur_ms` を同時に更新し、`p_onset_corrected_by_consensus` フラグを追加します。

2. 明らかに異常値である生の `p.offset` の場合:
   - 十分なサポートと適切な拡散を備えた P オフセット クラスターが存在する必要があります。
   - 生のオフセットとコンセンサス オフセットの差は少なくとも約 `20 ms` です。
   - 修正後は `p_onset < p_peak < p_offset` を満たす必要があります。
   - P 期間と PR セグメントは合理的である必要があります。
   ・修正後は生の`p_dur_ms`も同時に更新され、`p_offset_corrected_by_consensus`フラグが追加されます。

このステップの焦点は、単にグローバル PR を修正するのではなく、元のビート/リード レベルの境界を改善することです。 LUDB スポットチェック：

- レコード 2: aVL や V1 などの一部のリードの生の PR がマルチリードのコンセンサスに向けてプルされます。 aVR/V3/V5/V6 などのピークの短い PR 誤検知が依然として存在しており、これらは誤って選択された疑いがあり、ハード修復されていません。
- レコード 5: 12 のリードビート行の生の P オフセットがコンセンサスによって修正され、オフセットの分散が減少します。
- 12 PR 外れ値 小規模バッチの場合、PR MAE は基本的に第 3 段階と同じですが、わずかに優れています: 約 `40.40 ms -> 40.07 ms`。

これは次のレベルの問題も明らかにします。リード自体の P ピークが QRS に近い誤った偏向を選択する場合、オンセット/オフセットを移動するだけでは安全ではありません。実行すべき次のステップは、P ピーク/候補レベルの再選択または抑制であり、好ましくは生リズム残差、I/II + V1-V6 誘導選択、ベースライン活動閾値、テンプレート類似性、および `P wave` 文書の PR/PP 一貫性と組み合わせることができます。

<a id="15-已实现的第五阶段修改短-pr-假-p-candidate-抑制"></a>
### 1.5 実装された第 5 段階の修正: short PR false P 候補抑制

第 4 段階は、「同じ P ピークが依然として信頼できる」という前提の下で、オンセット/オフセットをシフトするだけです。一部のリードでは、P ピーク自体が QRS より前のローカル エイリアスを選択しています。このとき、オンセット/オフセットをグローバルの合意位置に強制的に移動すると、不合理なジオメトリが生成されます。したがって、現在、保守的な候補抑制が追加されています。

1. 強力な生理学的 P 開始クラスターが存在する必要があります。
2. 現在のリードの生の PR が明らかに短すぎます (たとえば、約 `100 ms` 未満)。
3. クラスター PR は、生の PR より少なくとも約 `50 ms` 長くなります。
4. 現在のリードの P ピークがクラ​​スターの開始から離れすぎており、単一の P 波の開始からピークまでの許容範囲を超えています。
5. 上記の条件が満たされたら、リード/ビートの生の P `WaveBounds`、`pr_ms`、P 振幅/面積、および P 形態派生フィールドをクリアし、以下を追加します。
   - `p_candidate_suppressed_by_consensus`
   - `p_unreliable`

このステップの目標は、「見栄えの良い P 波を作成する」ことではなく、偽の P 候補を代表、P 軸、P 形態に伝播するのをやめ、ピーク自体が信頼できない場合に報告することです。

LUDB スポットチェック：

- レコード 2: QRS に近い aVR/V3/V5/V6 などの短い PR の誤った候補が大幅に減少します。グローバル PR は、第 4 段階の `175.5 ms` から `181.0 ms` に調整されます。 GT `196.5 ms`と比較すると、誤差は`-21.0 ms`から`-15.5 ms`に改善されています。リードごとの PR では、aVR が非常に短い `94 ms` から `164 ms` に改善され、誤った P が報告され続けることを避けるために V6 が N/A になります。
- レコード 22: グローバル PR が `125.0 ms` から `148.0 ms` に調整されます。 GT `170.0 ms`と比較すると、誤差は`-45.0 ms`から`-22.0 ms`に改善されています。
- 12 個の PR 異常値の小さなバッチでは、PR MAE は第 4 段階の約 `40.07 ms` から約 `37.69 ms` までさらに低下しました。

これは依然として候補者の抑制であり、完全な候補者の再選択ではありません。次のより大規模な実装は、`P wave` ドキュメントに基づく必要があります。生のリズム残差または代表的な波形候補セットから P ピークを再選択し、テンプレートの類似性、PR/PP の一貫性、デュアル リード サポート、およびベースライン アクティビティのしきい値を使用してスコアを付けます。

<a id="16-已实现的第六阶段修改p-peak-上游融合锚点重选"></a>
### 1.6 第 6 段階の修正を実装: P ピーク上流融合アンカー ポイントの再選択

第 5 段階では、明らかに誤った短い PR の偽 P 候補が伝播し続けるのを防ぐことができますが、それでも本質的には「抑制」です。オリジナルの波形検出自体をより正確にするために、現在は各リード/ビートの P ピーク選択段階に改良が移されています。

実装のポイント:

1. `delineate_beats(...)` のすべてのリード P 検索において、`_fused_p_peak` は、検索ウィンドウを狭めるため、または大きさが完全に等しい場合に関係を破るためだけに使用されることはなくなりました。
2. `_select_p_peak_with_fused_anchor(...)` を追加しました:
   - 融合した P ピークは、電流リードの P 検索ウィンドウ内になければなりません。
   - 融合された P ピーク振幅は、そのリードの P 最小振幅閾値に達する必要があります。
   - 現在の abs モード ピークが QRS に著しく近く、融合ピークから QRS までの距離が妥当な P ピーク範囲内にある場合、融合ピークに戻ることが許可されます。
   - 2 つの振幅が近く、融合されたピークの方がタイミングと一致している場合は、融合されたピークに戻ることも許可されます。
3. このロジックは、最初の P ピーク検索と、P ピークが生理学的ウィンドウの外側にあると判断された後の制約された再検索の両方に使用されます。
4. 条件は、レコード ID や LUDB 固有のルールを使用せず、ローカル波形振幅、QRS 基準点、サンプリング レート、および既存のマルチリード フューズド アンカーのみに依存します。

このステップと第 5 ステージの違いは、ピークが信頼できなくなったときに第 5 ステージが P をクリアすることです。第 6 段階では、境界測定の前に、より信頼できる P ピークの選択を試みます。したがって、誤った候補を単に隠すのではなく、後続の `p_unreliable` および P の削除を減らすことができます。

LUDB 外れ値スポット チェック:

- レコード 2: グローバル PR は、第 5 段階の `181.0 ms` から `183.0 ms` に調整されます。 GT `196.5 ms` と比較すると、誤差は `-15.5 ms` から `-13.5 ms` に改善されています。 P欠損は`37`から`34`に減少します。
- レコード 22: グローバル PR が `148.0 ms` から `154.0 ms` に調整されます。 GT `170.0 ms` と比較すると、誤差は `-22.0 ms` から `-16.0 ms` に改善されています。 P欠落は`29`から`28`に減少します。
- レコード 23: グローバル PR は変化しませんが、P 欠損は `12` から `11` に減少します。
- レコード 182: グローバル PR は `136.58 ms` を維持しますが、これは依然として GT `134.0 ms` に非常に近いです。 P の削除は `3` から `2` に減少します。
- 小さなバッチの 12 個の PR 外れ値の場合、PR MAE は、第 5 段階の約 `37.69 ms` から約 `37.07 ms` までわずかに低下しました。

これはまだ完全な生リズム残留/テンプレート類似性再チェックではありませんが、「コンセンサス」を最終 PR レポートから元の P ピーク選択に、より直接的に元の `WaveBounds` の品質に移しました。

<a id="17-已实现的第七阶段修改p-peak-cluster-支持度融合"></a>
### 1.7 第 7 段階の修正を実装: P ピーク クラスター サポート フュージョン

第 6 段階では、「単一のリードが検索ウィンドウ内で間違ったピークを選択する」という問題は解決されますが、`_fused_p_peak` 自体は、依然としていくつかの高振幅リード、または QRS の開始近くの一般的な小さな変動によってバイアスされる可能性があります。ビートレベルの P ピーク プリパス フュージョンは現在さらに強化されています。

実装のポイント:

1. `_fuse_peak_anchor(...)` はオプションのリードごとの正規化を追加します。
   - 各リード候補は最初にこのリード内で正規化され、高振幅リードが絶対振幅を使用して多すぎるリードの低振幅 P コンセンサスを圧倒するのを防ぎます。
   - クラスター スコアリングでは独自のリード サポートを使用します。同じリードに対する複数の候補者が二度投票することはありません。
2. P ピーク プリパス コールはこのモードを有効にします。 T ピーク フュージョンは、T 波検出の妨げを避けるために、元の振幅/面積戦略を維持します。
3. P-to-QRS の生理学的制約を P ピーク クラスター スコアに追加します。
   - qrs リファレンスは、以前を表す QRS オンセットを優先するように変更されました。
   - 以前に QRS オンセットがない場合、R ピークを直接使用する代わりに、`R - 20 ms` を近似 QRS オンセットとして使用します。
   - このようにして、QRS の開始付近の短い間隔の偽クラスターは、R​​ ピークからまだ数十ミリ秒離れているため、妥当な P ピークとして誤って判断されなくなります。
4. 短い QRS 隣接クラスターのペナルティを強化します。これ以上合理的な代替手段がない場合は、それを選択することもできますが、適切なタイミングの P クラスターがある限り、後者が優先されます。
5. グローバル PR コンセンサスに raw サポート ガードを追加します。
   - グローバル PR を引き継ぐには、単一または少数の異常なリードが通常の PR を長い PR に引き伸ばすことを避けるために、長い PR クラスターにはクラスターの近くに少なくとも 2 つの生の PR 値が必要です。
   - 生の中央値が長い PR 外れ値によって引き上げられ、強力なオンセット クラスターに十分な生のサポートがある場合、クラスターは下方へ救済されることが許可されます。
   - 生の代表 PR が非常にまばらな場合、単一リードの生 PR がグローバル PR を決定するのではなく、強力なオンセット クラスターを使用することを優先します。

このステップは第 6 段階よりも上流にあり、特定の融合アンカーの後に各リードが修正されるだけでなく、融合アンカーの生成段階では、「リードごとに 1 票 + 複数リードのサポート + QRS 開始タイミング」がアンカー自体の偏りを防ぐために使用されます。

<a id="2-当前-p-波检测流程"></a>
## 2. 現在の P 波検出プロセス

<a id="21-代表波形-prior"></a>
### 2.1 前の代表的な波形

コードはまず、各グループ/リードの代表的な拍前を構築します。

- `build_group_priors(...)` は、`representative_beats` から各グループおよび各リードの代表波形を抽出します。
- `_delineate_rep_prior(...)` は、代表的な波形上で P/QRS/T の先験的な位置を探します。
- P 波事前では、現在 `_find_peak(...)` を使用して P ピークを見つけ、次に `_find_wave_bounds(..., frac=0.08)` を使用して P オンセット/オフセットを推定します。

この事前分布の価値は、後続のビートレベル検出に比較的安定した時間ウィンドウを提供できるため、ビートごとに最初から検索する自由度が減少することです。

ただし、ここには 2 つの制限があります。

1. 事前の波形を表す P オンセット/オフセットは依然として閾値境界であり、マルチリードのコンセンサス境界ではありません。
2. 現在の代表的な波形は多くの場合、中央値/単一 representative beat であり、必ずしも中央値/平均テンプレートである必要はありません。形態学的忠実度は優れていますが、低振幅の P 波境界ノイズの低減には十分ではありません。

<a id="22-每个-beat-的多-lead-p-peak-预融合"></a>
### 2.2 各拍動に対する複数のリード P ピークの事前融合

各拍の P 検索ウィンドウで、アルゴリズムは最初にすべてのリードから P 候補を検索します。

- `_candidate_triplets(...)` は、リードごとに P 個のピーク候補を生成します。
- `_fuse_peak_anchor(...)` は、振幅、面積、以前の近接性、および信頼できるリードの重みに基づいて、複数のリード候補を 1 つの `_fused_p_peak` にマージします。

このステップは、現在の P 波検出における最も明確な「コンセンサス」の使用ポイントです。その機能は、すべてのリードに共通の P ピーク アンカー ポイントを与え、各リードが完全に異なる局所変動を選択するのを防ぐことです。

しかし、それにはリスクもあります。

- 融合ピークが偽の P、T テール残基、または QRS に近いベースライン変動によって引き付けられた場合、後続のすべてのリードの P 検索ウィンドウにバイアスがかかります。
- 現在のフュージョンは主にピーク インデックスを返しますが、リード番号、クラスターの広がり、候補クラスター間の競合のサポートなど、十分な出所が不足しています。
- P ピーク コンセンサスは、P オンセット/オフセットが正しいことを直接保証できません。 P ピークが安定している場合でも、低振幅の開始点と終了点、およびベースラインの不安定性により、境界が大幅にシフトする可能性があります。

<a id="23-每个-lead-的-p-onsetoffset"></a>
### 2.3 各リードのオンセット/オフセット

各リードにおける P 検出の主なプロセスは大まかに次のとおりです。

1. `_fused_p_peak` または前の代表的な波形に基づいて P 検索ウィンドウを絞り込みます。
2. `_find_peak(..., mode="abs")` を使用して、ウィンドウ内の P ピークを見つけます。
3. `_select_p_peak_with_fused_anchor(...)` を使用して、abs モードのピークが QRS に近い偽ピークによって吸い取られているかどうかを確認します。融合 P ピークの振幅が標準に達し、タイミングがより合理的である場合は、融合アンカーに戻る P ピークを選択します。
4. P ピークから R/QRS までの距離が生理学的範囲内であるかどうかを確認します。制約付きの再検索が必要な場合は、融合アンカー選択も再度適用します。
5. タンジェント法を使用して P オンセットを推定します。
   - 現在の通話は `_t_onset_tangent(...)` です。
6. `_p_offset_tangent(...)` を使用して P オフセットを推定します。
7. 必要に応じて、`_rescue_long_pr_p_onset(...)` を使用して、長い PR フォワードの開始をレスキューします。
8. 幾何学的関係が異常な場合、`_p_wave_qrs_geometry_mode(...)` は P をクリアするか、P onset をクリアする可能性があります。

これは、各リードの P オンセット/オフセットが主に局所的な幾何学的結果になることを意味します。これらは次の影響を受けます。

- P 波の振幅が低く、導関数と接点はノイズによって支配されやすくなります。
- ベースラインが少し偏っていると推定される場合、オンセット/オフセットは大きく移動します。
- P 波は二相性で、ノッチがあり、低く、単一の接点が不安定です。
- オフセット検索の終点は `qrs_on - 1` までとなります。 PR セグメントが低い振幅で変動する場合、または QRS の開始点が不安定な場合、オフセットは簡単に QRS に近づきすぎてしまう可能性があります。
- フォールバックの `_find_wave_bounds(..., frac=0.08)` は振幅とローカル ノイズの影響を受けやすく、リードが異なると P 持続時間の長さも異なります。

<a id="24-当前-multi-lead-consensus"></a>
### 2.4 現在の複数のリードのコンセンサス

`_apply_multilead_consensus(...)` は、同じビートの複数のリード結果に対してコンセンサス処理を実行します。

P 波関連分野に関して、現時点で最も重要なものは次のとおりです。

- 信頼できるリード `bf.p.onset` を収集します。
- 以前の分位数を使用して `global_p_onset` を計算します。
- 各リードの `pr_consensus_ms` を導出します。

しかし、ここには重要なギャップがいくつかあります。

1. **P オフセットのコンセンサスは計算されません。 **
2. **P 期間コンセンサスは計算されません。 **
3. **コンセンサス オンセット/オフセットは最終的な `WaveBounds` に書き戻されません。 **
4. **`global_p_onset` は単純な分位数を使用し、候補クラスタリングとクラスタ サポートの判断を欠いています。 **
5. **後続のグローバル PR では、主に `pr_consensus_ms` をメイン パスとして使用しません。 **

したがって、現在の P 境界の「コンセンサス」強化は、完全な閉ループではなく、部分的かつ間接的なものです。

<a id="4-为什么-p-onset-和-p-offset-容易错"></a>
## 4. P onset と P offset が間違いやすい理由

<a id="41-p-波信号本身弱"></a>
### 4.1 P波信号自体が弱い

P 波は通常、振幅が小さく、傾きが低く、明確なピークで始まり、終わることはありません。 QRS オンセットには通常、より明らかな傾き変化があり、T オフセットはより長い単峰性/二峰性形態を利用でき、P オンセット/オフセットは以下の要因の影響を受けやすくなります。

- ベースラインワンダー
- EMGノイズ
- P波は低くフラット
- P 波二相性またはノッチ
- PRセグメントは若干変動
- QRS 開始検出のわずかなずれ

したがって、1リード1ビートのローカルタンジェント法では当然安定性が十分ではありません。

<a id="42-p-onset-被-fused-peak-窗口牵引"></a>
### 4.2 P オンセットは融合されたピーク ウィンドウによってプルされます

現在の P ピークが事前融合された後、各リードの P 検索ウィンドウは、`_fused_p_peak` または代表的な以前の付近に狭められます。融合されたピークが正しい場合、安定性が大幅に向上します。しかし、融合したピークが間違った候補に引き寄せられると、すべてのリードが間違ったタイミングで P 波を探すことになります。

これにより、一種の「誤った同期」が発生します。

- 複数のリードがローカル ウェーブレットを見つけることができます。
- これらのウェーブレットは時間的に近く、コンセンサスがあるように見えます。
- しかし、これらは実際には、QRS より前の低振幅ノイズ、T/P 混乱、または PR セグメント変動です。

したがって、P ピーク コンセンサスはクラスターのサポートと競合クラスターの情報を出力する必要があり、ピーク インデックスのみを出力することはできません。

<a id="43-p-offset-没有跨-lead-校验"></a>
### 4.3 P オフセットはリード間で検証されていません

Pオフセットは現在主に`_p_offset_tangent(...)`を使用しており、`qrs_on - 1`を検索しました。 PR セグメントが変動する場合、または QRS の開始がわずかにずれている場合、オフセットは QRS の非常に近くまでドラッグされる可能性があります。

オフセットが遅すぎると、次のような結果になります。

- P 持続時間が長すぎます。
- PRセグメントは圧縮されています。
・Pエリアが大きすぎます。
・P端子力が正しく拡張されていない可能性があります。
- P ノッチ/バイフェーズ判定は、PR セグメントまたは QRS 事前変動によって汚染される可能性があります。

オフセットが早すぎると、次のような問題が発生します。

- P 持続時間が短すぎます。
-P 端子コンポーネントは切り捨てられます。
- 二相 P 波の後半の損失。
- P エリアと PTF は過小評価されています。

これは、レコード 5 のオフセット散乱の問題です。

<a id="44-p-confidence-不是边界-confidence"></a>
### 4.4 P 信頼度は境界信頼度ではありません

現在、`p_confidence` は主に P 振幅、ノイズ フロア、検出サポートに関連しています。リードの P 振幅が高く、`p_confidence` である場合でも、オンセット/オフセットが間違っている場合があります。

したがって、分割する必要があります。

- `p_presence_confidence`: P 波が存在するかどうか。
- `p_peak_confidence`: P ピークは信頼できますか?
- `p_onset_confidence`: 開始は信頼できますか。
- `p_offset_confidence`: P オフセットが信頼できるかどうか。
- `p_boundary_consensus_support`: 境界が複数のリード/代表波形でサポートされているかどうか。

そうしないと、その後のコンセンサスで「P の存在は非常に信頼できる」と「P の境界は非常に信頼できる」と誤解されてしまいます。

<a id="5-是否可以用共识加强"></a>
## ５ 「合意」によって強化できるのでしょうか？

はい、P 波のコンセンサスを 4 つの層に分割することが推奨されます。

<a id="51-第一层p-peak-候选聚类共识"></a>
### 5.1 第 1 層: P ピーク候補クラスタリングのコンセンサス

現在、`_fuse_peak_anchor(...)` は、リードごとの正規化、独自のリードのサポート、および P から QRS の開始タイミングに従って、P ピーク融合の強化を開始しています。ただし、それでも選択された 1 つのピークのみが返されるため、引き続き出力を候補クラスターに拡張することをお勧めします。

- 各クラスターの中心時間。
-サポートリード番号。
- 四肢、下位、前胸部などのリード領域をサポートします。
- クラスター内の時間の分散。
- クラスター内のマグニチュード/面積加重分数。
・以前の代表波形に近いかどうか。
- 適切な PR 間隔が満たされているかどうか。

単に融合されたピークを返すのではなく、以下を返します。

- `selected_p_peak`
- `selected_cluster_support`
- `selected_cluster_spread_ms`
- `competing_clusters`
- `selection_reason`

このようにして、後続のオンセット/オフセットにより、現在のピークアンカーポイントが安定しているかどうかを知ることができます。

<a id="52-第二层p-onset-边界共识"></a>
### 5.2 第 2 層: 開始境界のコンセンサス

各ビートについて、信頼できるリードごとに生の P オンセットを取得した直後に P10 を使用するべきではありません。提案:

1. 信頼できるリードの生の開始を収集します。
2. 明らかに不合理な候補者を排除します。
   - P オンセットは P ピークより遅い。
   - すでにペーシング/逆行/AV ブロックなどのコンテキストが存在しない限り、PR が短すぎるか長すぎます。
   - P 持続時間が緩和範囲外です。
   - オンセットは、現在選択されている P ピークと同じ P 波形に属しません。
3. クラスターの発症時間。
4. P ピーク クラスター、事前の代表的な波形、およびリード サポートと一致するオンセット クラスターを選択します。
5. 堅牢な統計を使用して、中央値またはわずかに早いパーセンタイルなど、クラスター内での開始のコンセンサスを取得します。

ここで重要なのは、P 発症の場合、早期発症と後期発症ではコストが異なるということです。

- PR を測定したい場合、遅発性は体系的に PR を過小評価することになります。
- ただし、開始が早すぎる場合、T 波尾/ノイズが P に含まれます。

したがって、全体的な開始には P10 の代わりにクラスター内の堅牢な初期境界を使用することをお勧めします。

- 強力なクラスターのサポートと小さな広がり: クラスター P25 または中央値を使用できます。
- クラスターは一般をサポートします: 中央値を使用し、信頼性を低く保ちます。
- 長い PR クラスターと短い PR クラスターの間には競合があります。最大振幅に基づいて選択するだけでなく、事前の代表的な波形、リード領域のサポート、および P ピークの一貫性を優先してください。

<a id="53-第三层p-offset-边界共识"></a>
### 5.3 第 3 層: P オフセット境界のコンセンサス

今一番不足している層です。

ビートごとに計算することをお勧めします。

- `p_offset_consensus_idx`
- `p_duration_consensus_ms`
- `pr_segment_consensus_ms`
- `p_offset_support_leads`
- `p_offset_spread_ms`

候補者のルール:

1. 信頼性の高い各リードは生の P オフセットを提供します。
2. 明らかな異常なオフセットを削除します。
   - オフセットはピークよりも前です。
   - 明示的に短い PR/事前励起を除いて、オフセット遅延到着が QRS 開始に近すぎる。
   - P 持続時間が緩和された上限を超えています。例: 160～180msを超えており、強い二峰性/異常な形態の証拠はありません。
   - P 持続時間が短すぎます (たとえば、40 ～ 50 ミリ秒未満)。
3. オフセット候補をクラスタリングします。
4. オンセットコンセンサスと P ピークコンセンサスを備えた妥当な P 期間を形成するクラスターを優先します。
5. PR セグメント ガードを追加します。
   - 通常の状況では、`p_offset` は `qrs_onset` よりも少し前にあるはずです。
   - オフセットが QRS に近い場合、複数のリードからの強力なサポートがなければなりません。そうでない場合は、QRS より前のノイズ/PR セグメントの変動とみなされます。

レコード 5 のシナリオでは、オフセット コンセンサスにより、一部のリードのオフセットが R の 40 ミリ秒前にドラッグされるのを防ぐことができ、また、他のリードが途中で切り捨てられることも防ぐことができます。最終的な P 持続時間は、複数のリードによってサポートされる範囲内に収まる必要があります。

<a id="54-第四层代表波形模板共识"></a>
### 5.4 4 番目の層: 波形テンプレートのコンセンサスを表します

現在の medoid representative beat を保持することをお勧めしますが、特に低振幅境界用に追加の中央値/トリミング平均テンプレートを作成します。

- medoid: 真の形状を保持し、表示や局所的な形態計測に適しています。
- 中央値テンプレート: ランダム ノイズを低減し、P オンセット/オフセット境界に適合します。

プロセスは次のとおりです。

1. R ピークを押して、同じグループ内のビートを揃えます。
2. 各リードの中央値テンプレートを構築します。
3. テンプレートのオンセット/オフセットを検出します。
4. テンプレート P 境界をビートごと/リードごとの事前制約またはソフト制約として使用します。
5. ビートごとの生の境界とテンプレートの境界の差が大きすぎるが、それをサポートする複数のリードがない場合は、それをダウングレードするか、コンセンサスに置き換えます。

これは、P 波境界の振幅が低く、ビート間のノイズの影響が大きいため、P onset/offset に特に利益をもたらします。

<a id="6-建议的改进设计"></a>
## 6. 提案される設計の改善点

<a id="61-数据结构层面"></a>
### 6.1 データ構造レベル

ビートレベルのフィーチャに次の来歴フィールドを追加または保持することをお勧めします。

- `p_onset_raw_ms`
- `p_offset_raw_ms`
- `p_onset_consensus_ms`
- `p_offset_consensus_ms`
- `p_duration_consensus_ms`
- `p_peak_consensus_support`
- `p_onset_consensus_support`
- `p_offset_consensus_support`
- `p_boundary_spread_ms`
- `p_boundary_confidence`
- `p_boundary_source`

`p_boundary_source` は次の方法で取得できます。

- `raw_local`
- `lead_consensus`
- `template_prior`
- `template_and_lead_consensus`
- `suppressed`

このようにして、後続のデバッグで各 P 境界がどこから来たのかを知ることができます。

<a id="62-算法层面"></a>
### 6.2 アルゴリズムレベル

次の順序で変更することをお勧めします。

1. **機能強化 `_fuse_peak_anchor(...)`**
   - シングルピーク出力からクラスターレベル出力に変更されました。
   - リード、クラスターの広がり、および候補競合情報のサポートを維持します。

2. **新しく追加された `_cluster_p_boundaries(...)`**
   - 同じビートの複数のリード生 P オンセット/オフセットを入力します。
   - コンセンサスのオンセット、オフセット、期間、サポート、スプレッドを出力します。

3. **`_apply_multilead_consensus(...)` の拡張**
   - 現在、`pr_consensus_ms` のみが派生されています。
   - P onset consensus、P offset consensus、P duration consensus を追加します。
   - 信頼性の低い raw boundary に対して減権またはマークを付与します。

4. **グローバル PR 集計の修正**
   - 現在、`_global_pr_median(...)` は主に raw limb PR を使用しています。
   - consensus のサポートが強く、raw limb spread が大きい場合、supported consensus PR を優先して使用することを推奨します。
   - ただし、`pr_consensus_ms` を無条件で使用することはできず、cluster support と生理学的制約が必要です。

5. **代表波形に median template を追加**
   - medoid は引き続き保持します。
   - median template は P 境界の事前確率（prior）に使用します。

6. **P 形態学的特徴に境界の信頼度を使用**
   - P area、P terminal force、notched/biphasic については、raw boundary を使用しているか consensus boundary を使用しているかを記録する必要があります。
   - 境界の信頼度が低い場合、形態学的な結論も格下げする必要があります。

<a id="63-选择-consensus-的建议规则"></a>
### 6.3 consensus 選択の推奨ルール

まず保守的なバージョンを使用できます：

1. 信頼できる P リードが3本未満の場合、raw boundary を強制的に上書きせず、consensus の低信頼度を記録するのみとします。
2. onset cluster support >= 3 かつ spread <= 20ms の場合、high-confidence onset consensus を生成できます。
3. offset cluster support >= 3 かつ spread <= 25ms であり、かつ P duration が合理的な範囲内にある場合、high-confidence offset consensus を生成します。
4. raw PR median と consensus PR の差異が > 40ms の場合、以下を確認します：
   - どちらがより多くのリードのサポートを持っているか。
   - どちらが代表テンプレートの事前確率（prior）により近いのか。
   - どちらがより合理的な P duration と PR segment を生成するか。
5. 2つの P onset cluster（1つは短い PR、もう1つは長い PR）が存在する場合：
   - 時間の早晚だけで直接選択しません。
   - P peak cluster が同源性を持っているかを確認します。
   - limb/inferior lead がサポートしているかを確認します。
   - テンプレートの事前確率（prior）がサポートしているかを確認します。
   - その cluster の P duration/offset が生理学的に合理的かを確認します。

<a id="7-优先修复点"></a>
## 7. 優先修復ポイント

<a id="p0不要只把-prconsensusms-当旁路字段"></a>
### P0：`pr_consensus_ms` を単なる副次的なフィールドとして扱わないこと

記録39は、現在の `pr_consensus_ms` がグローバル PR よりも明らかに優れている場合があるが、グローバル PR でそれが使用されていないことを示しています。まず保守的なゲートリング（gating）を実装することを推奨します：

- raw limb PR spread が非常に大きい場合；
- かつ consensus PR support が十分である場合；
- かつ consensus PR が代表波形の事前確率（prior）と一致する場合；
- かつ consensus PR が合理的な生理学的範囲内にある場合；

グローバル PR は consensus PR または consensus/raw の混合推定値を使用します。

このステップにより、P onset が遅れて PR が短くなる症例の一群をまず改善できます。

<a id="p1增加-p-offset-consensus"></a>
### P1：P offset consensus の追加

P offset は現在最大のギャップです。すべてのリードの `WaveBounds` をすぐに上書きするのではなく、まず以下のフィールドを追加することを推奨します：

- `p_offset_consensus_ms`
- `p_duration_consensus_ms`
- `p_offset_consensus_support`

その後、representative/global features で、高いサポート度を持つ consensus P duration を優先して使用します。

<a id="p2把-p-boundary-confidence-从-p-presence-confidence-中拆出来"></a>
### P2：P boundary confidence を P presence confidence から分離する

分離しない場合、後続で「P の存在は確実だが、境界が非常に誤っている」という状況が引き続き発生します。boundary レベルの信頼度を追加し、P area/PTF/notched/biphasic でそれを使用することを推奨します。

<a id="p3代表波形从-medoid-扩展到-median-template"></a>
### P3：代表波形を medoid から median template へ拡張

P 波の境界は低振幅の問題であり、median template は単一のビート medoid よりも onset/offset に対して安定しています。medoid を代表表示として保持し、median template を境界の事前確率（prior）として追加することを推奨します。

<a id="8-推荐验证集"></a>
## 8. 推奨検証セット

以下の記録を中心に回帰検証を行うことを推奨します：

- **記録 5**：P offset consensus がリード間の offset の分散を減少させるかどうかを重点的に検証します。
- **記録 39**：supported consensus PR がグローバル PR の短さを修正できるかどうかを重点的に検証します。
- **記録 57**：naive consensus が PR を誤った短い PR に引きずらないようにします。
- **記録 120**：長い PR をサポートするリードが存在する場合、アルゴリズムが短い PR の偽候補に支配されないかどうかを検証します。
- **記録 130**：fused peak が誤っている場合、cluster/provenance が低信頼度を識別し、誤ったコンセンサス化を行わないかどうかを検証します。

推奨される自動チェック：

1. PR MAE が低下しているか。
2. PR bias が現在の約 `-11.8 ms` から 0 へ収束しているか。
3. PR > 20ms の外れ値の数が減少しているか。
4. P duration のリード間 IQR が減少しているか。
5. P offset から QRS onset への異常な近接の割合が減少しているか。
6. P area/PTF の異常に大きな値が減少しているか。

<a id="9-小结"></a>
## 9. まとめ

現在の P 波検出の問題は、単なる閾値の緩すぎや厳しすぎではなく、P 境界がまだ「マルチリード、マルチビート、代表波形」の完全なクローズドループを形成していないことにあります。

現在、非常に良い基盤が整っています：

- per lead/per beat の結果が完全です；
- 代表波形の事前確率（prior）が存在します；
- P peak はすでにリード間融合が行われています；
- `pr_consensus_ms` は一部の症例でより良い情報を捕捉できています。

次のステップでは、コンセンサスを P peak から P onset/P offset/P duration へ推進し、グローバル PR と P 形態学的特徴が実際にサポートされた consensus boundary を使用するようにする必要があります。これにより、P onset の遅れ、P offset の分散、P duration の不安定さ、およびそれらに起因する PR/PTF/P morphology の誤差を体系的に改善できます。

<a id="10-qrst-residual-raw-p-event-反哺更新"></a>
## 10. QRST residual raw P event によるフィードバック更新

`/home/chtmedgemma/projects/ecg_gemma/P wave` における raw rhythm P/atrial activity のアプローチを参考に、現在の実装ではより完全でありながら依然として保守的なクローズドループを補完しました：

1. `feature_extraction/ecgfeat/atrial.py` 内の composite QRST-residual detector は、P event の peak/sample のみを出力するのではなく、`onset_sample`、`offset_sample`、`duration_ms`、`amplitude_mv`、`area_mv_ms`、`signed_area_mv_ms`、`template_similarity`、`pp_ms` などの測定フィールドも同時に出力します。
2. `feature_extraction/ecgfeat/delineate.py` は、リードごと/心拍ごとの P コンテキストをスコアリングした後、複合生 P 検出器を呼び出して、信頼性の高い生の心房イベントを心拍/リードに対応する P 代替に変換します。
3. 生のイベントは、元の P 検出を直接カバーしません。テンプレートの類似性、PR の一貫性、PP の一貫性、およびマルチリードのサポートを候補として備えている場合にのみ、再選択ゲートに入ることができます。
4. 通常の代替案では、やはり `old_score < 0.50` の候補のみが検査されます。生の残差イベントは、`old_score < 0.65` の境界線の候補を調べることができますが、最終的には明らかなコンテキストの改善を満たさなければなりません。
5. エクスポート層は、その後のリズム分析、AV ブロック/ブロックされた P 検査、および P 検出品質のデバッグを容易にするために、生の P イベントの新しい測定フィールドを保持します。

- `tmp_p_raw_atrial_context_full/summary.csv` は、現在の `ludb_full_compare/summary.csv`、PR/QRS/QT/QTc/T 軸/QT の分散/欠落カウントと比較して変更はありません。
