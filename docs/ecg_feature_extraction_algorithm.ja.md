# ECG 特徴抽出アルゴリズムのロジックとプロセスの説明

この文書は現在の倉庫コードに基づいており、日付は 2026-07-06 です。コアの実装は次のとおりです
`feature_extraction/ecgfeat` の下の `ECGFeatureExtractor.extract()`、全体
DXL からインスピレーションを得た 12 リード ECG 特徴抽出プロセス (フィリップス DXL 独自のアルゴリズムではない)
行ごとの再現は実証済みの医療機器ソフトウェアではありません。

<a id="1-入口与整体数据流"></a>
## 1. エントリと全体的なデータ フロー

<a id="11-主要入口"></a>
### 1.1 正面玄関

|シナリオ |ファイル/関数 |機能 |
| --- | --- | --- |
|シングルレコードのデモ | `demo_feature_extraction.py` |ローカルの `dataset/*.mat/.hea` から ECG と患者情報を読み取り、エクストラクターを呼び出し、`*_features.json`、レポートと視覚化を生成します。 |
| `.pt` データのバッチ | `batch_extract_ecgfeat.py` |バッチ入力形状を正規化し、サンプルごとにエクストラクターを呼び出し、JSON/PT/report/manifest を保存します。 |
|アルゴリズムメインエントランス | `feature_extraction/ecgfeat/api.py::ECGFeatureExtractor.extract` |完全な特徴抽出、ペーシング/リズム戦略、解釈レイヤー、メタデータのアセンブリ。 |
|エクスポート | `feature_extraction/ecgfeat/export.py::to_dict` |データクラスの結果を JSON フレンドリーな構造に展開し、`rhythm_inputs`、`morphology_inputs`、`statement_engine` を追加します。 |

<a id="12-输入约定"></a>
### 1.2 入力規則

中心的な入力は次のとおりです。

- `ecg_12lead`: `numpy.ndarray`、予想される形状は `[12, n_samples]`、単位は mV です。
- `fs`: 元のサンプリング レート。
- `meta`: 大人/子供のルール ルーティング、性別関連のしきい値、レポート コンテキスト用のオプションの `PatientMeta(age, sex, meds)`。

ECG 入力が `[n_samples, 12]` の場合、エクストラクターは自動的に転置されます。 12 行も 12 列もない場合、`ValueError` がスローされます。

標準のリードシーケンスは次のように固定されています。

```text
I, II, III, aVR, aVL, aVF, V1, V2, V3, V4, V5, V6
```

<a id="13-主流程总览"></a>
### 1.3 メインプロセスの概要

```text
输入 ECG
  -> 采样率统一和双路预处理
  -> 导联质量评估、导联反接检测、起搏 spike 检测
  -> 多导联 QRS/R 峰检测
  -> 起搏 spike 与 QRS 校验，必要时去 spike 后重跑 QRS
  -> beat grouping 和 measurement group 选择
  -> representative beat 构建
  -> 逐搏逐导联 P/QRS/T 边界定位和基础测量
  -> 根据定位结果重新评估 measurement group
  -> atrial event、AF/AFL、起搏/AV block/preexcitation 规则输入
  -> measurement representative 和 representative lead 特征
  -> group/global 特征聚合，QT/PR/QRS rescue，axis 计算
  -> 12SL-style 并行 measurement profile
  -> rhythm availability 和 statement evidence
  -> clinical interpretation
  -> JSON 导出
```

<a id="2-预处理"></a>
## 2. 前処理

実装場所: `preprocess.py`

<a id="21-采样率"></a>
### 2.1 サンプリングレート

`fs_run` は構築パラメータによって制御されます。

- `fs_internal is None`: 入力 `fs` の丸められた整数を使用します。
- `fs_internal` 指定した場合: この内部サンプル レートにリサンプリングします。

リサンプリングでは、`scipy.signal.resample_poly` を使用して、入出力サンプリング レートの最大公約数に従って上限と下限のサンプリング比を簡素化します。

<a id="22-两路信号"></a>
### 2.2 2 つの信号

エクストラクターは、異なる目的のために 2 つの信号を保持します。

|信号 |構築方法 |目的 |
| --- | --- | --- |
| `ecg_an` / 測定信号 |ベースラインのドリフトを除去するための 2 段階のメディアン フィルタリング、デフォルトの 200 ミリ秒および 600 ミリ秒のウィンドウ。次に、電源周波数ノッチを実行します。ローパスはありません。 |すべての振幅、境界、ST/T/P/QRS 測定では、ピーク値を保持するように努めます。 |
| `ecg_det` / 検出信号 | `analysis_signal` を選択し、デフォルトの 40 Hz の 4 次ローパスを設定します。 | EMG ノイズを低減するための QRS/R ピーク検出にのみ使用されます。 |

<a id="3-质量评估与反接检测"></a>
## 3. 品質評価と逆接続検出

実装場所: `quality.py`

<a id="31-每导联质量"></a>
### 3.1 リードごとの品質

`compute_quality()` 各標準リードについて計算します。

- ベースラインワンダ: `0.5 Hz` 以下の傾向は、全体の標準偏差と相対的なものです。
- マッスルノイズ: `35-100 Hz` 周波数帯域パワー比。
- 電力線ノイズ: 電力周波数 `mains_freq +/- 1 Hz` 電力比。
- クリッピング: 隣接するスプレッドの比率を 0 にします。
- フラットライン/欠落: 標準偏差 `< 0.005 mV`。

出力 `LeadQuality`:

- 全体 `reliable`
- 波形固有の信頼性: `reliable_for_p`、`reliable_for_qrs`、`reliable_for_t`、`reliable_for_qt`
- `grade`: `Q0/Q1/Q2/Q3`
- `flags` および `reason_codes`

主なしきい値:

- P 波は QRS、ベースライン ワンダ `< 0.30`、筋肉 `< 0.20`、パワーライン `< 0.10` よりも厳しいです。
- QRS は、より高い筋電ノイズ、筋肉 `< 0.40`、電力線 `< 0.20` を許容します。
- QT では、T と QRS の両方が信頼できる必要があります。

`summarize_record_quality()` は、すべてのレコード内の信頼できるリードの数を要約し、次のようになります。

- `record_grade`
- `rejected_functions`: 例: `p_measurement`、`qt_measurement`、`record`
- グローバル理由コード

<a id="32-导联反接"></a>
### 3.2 リード線逆接続

四肢リード逆接続はヒューリスティックを使用します。

- アイントホーフェン関係エラー: `II - I - III`
- `I`、`-II`、`aVR`、`aVL/aVF`などのリード相関
- 出力 `probable_ra_la`、`probable_ra_ll`、`probable_la_ll`、`probable_extremity_reversal`

前胸部リード逆接続は、V1-V6 R 波の進行に基づいて代表的なリード相で検出されます。

- R 波進行スコアが低く、隣接する胸部リードのペアを交換した後に大幅に改善した場合は、`probable_precordial_reversal` をマークします。
- 低電圧胸部リード線の場合、この判定はスキップされます。

<a id="4-起搏-spike-检测与去-spike"></a>
## 4. ペーシングスパイクの検出とスパイクの除去

実装場所: `quality.py`、`api.py`

ペーシング ロジックは、測定信号、ビート フラグ、QRS 幅、および PR の可用性を変更するため、メイン フローにおける重要なバイパスです。

<a id="41-spike-候选"></a>
### 4.1 スパイク候補

デフォルトの検出器:

- 各リードの差分強化。
- ローリング MAD によるローカル ノイズの推定。
- 候補者は `4 * sigma` 動的しきい値を超える必要があります。
- スパイク幅の要件は `<= 6 ms` 程度です。
- デフォルトの絶対プロミネンスしきい値は `250 uV` で、高振幅スパイク基準しきい値は `1000 uV` です。

強力な証拠のフォールバックとして、従来のハイパス RMS 検出もあります。

<a id="42-多导联共识"></a>
### 4.2 複数のリードのコンセンサス

候補は約 `5 ms` ウィンドウごとにイベントにマージされます。イベントは以下を満たす必要があります:

- デフォルトで少なくとも 4 つのリード投票、または十分に高い弱い投票の重み付けスコア。
- スパイクが 3 つを超える場合、間隔の中央値の半分未満の隣接アーティファクトが削除されます。
- スパイク間隔が安定した CV `< 0.15` の場合、リズムはペーシングされていると見なされます。

<a id="43-qrs-校验与去除伪影"></a>
### 4.3 QRS の検証とアーティファクトの削除

最初の QRS 検出の後、`validate_pacing_spikes_against_qrs()` は、QRS エッジが誤ってスパイクとして認識される状況を排除します。

- 最も近い R ピークからスパイクのオフセットを計算します。
- スパイクの高周波ピークを QRS の高周波ピークと比較します。
- 幅が狭く、比較的 QRS 高周波エネルギーが支配的な場合に予約されます。
- 多数のスパイクが QRS と固定的に同期され、QRS エッジ アーティファクトに似ている場合は、スパイクをクリアして `qrs_edge_artifact` をマークします。
- 心房/非心室ペーシングの可能性は控えめに処理され、心室ペーシング測定には直接影響しません。

スパイクが確認された場合、`remove_pacing_spikes()` は各スパイク付近で `+-4 ms` ウィンドウ線形補間をデフォルトとして使用し、スパイク後の信号を使用して検出信号を再構築し、QRS を再実行します。

<a id="44-attenuated-pacing-rescue"></a>
### 4.4 減衰ペーシングレスキュー

初期ペーシングの証拠が不十分な場合、`api.py` はプロミネンスを `150/100/25 uV` のレスキュー パスまで下げようとします。このパスは、再スパイク、QRS の再実行、QRS キャプチャ検証に合格した後のダウンストリームにのみ影響します。

<a id="45-beat-级起搏状态"></a>
### 4.5 拍レベルのペーシング ステータス

スパイクが `R - 80 ms` から `R + 20 ms` の範囲内にあり、キャプチャ アラインメントが確立されている場合、ビートはペーシング済みとしてマークされます。これは後で生成されます。

- `paced_beat_ids`
- `pacing_spike_beat_ids`
- `pacing_spike_offsets_ms`
- `pacing_capture_confirmed`
- `pacing_detection_state`
- `measurement_pacing_state`
- `pacing_measurement_effect`
- `pacing_segmentation_effect`

<a id="5-多导联-qrsr-峰检测"></a>
## 5. 多リード QRS/R ピーク検出

実装場所: `qrs.py`

<a id="51-检测信号"></a>
### 5.1 検出信号

デフォルトでは、ベクトルの大きさを構築するためにリード `I, II, V2, V3, V4, V5, V6` が使用されます。

```text
VM = sqrt(mean(zscore(lead)^2))
```

後:

- バンドパス `5-25 Hz`
- エネルギーは最初の差を 2 乗することで得られます。
- `120 ms` 移動平均

<a id="52-阈值和-r-峰精修"></a>
### 5.2 しきい値と R ピークのリファインメント

主なしきい値:

```text
max(P95(energy) * 0.30, mean + 0.5 * std)
```

ピーク間の最小距離は約 `220 ms` です。各エネルギー ピークは、誘導 II ローカル波形を使用して、`+-50 ms` 内の R 位置を調整します。負の QS 優勢波形の場合、基準は S/QS 谷の後半ではなく、急峻な負の方向の始まりに配置されます。

エッジ保護: 不完全な測定を避けるために、記録エッジから `<160 ms` の距離にある候補は破棄されます。

<a id="53-robust-fallback"></a>
### 5.3 堅牢なフォールバック

メインの検出がまばらすぎる場合は、中央値/MAD に基づいた堅牢なしきい値が試行されます。結果が少なくとも 3 拍で堅牢で、妥当な検出率を持ち、メインの検出を大幅に補完する場合にのみ、メインの結果を置き換えます。

<a id="6-beat-grouping-与-measurement-group"></a>
## 6. ビートのグループ化と測定グループ

実装場所: `grouping.py`、`api.py`

<a id="61-beat-template"></a>
### 6.1 ビート テンプレート

各ビートは、`R - 80 ms` から `R + 120 ms` までの 12 リード セグメントを取得し、各リードを 32 点に補間し、平均を削除して正規化し、それをテンプレート ベクトルに接続します。

<a id="62-两阶段聚类"></a>
### 6.2 2 段階のクラスタリング

`cluster_beats()`：

1. ベクトルの大きさに基づいて QRS の幅を大まかに推定し、`<120 ms` と `>=120 ms` に従って狭い/広いカテゴリに分割します。
2. さまざまな内部オンライン形態クラスタリング、コサイン類似度 `>=0.88` は既存のグループに分類されます。
3. 最大 5 グループ、ワイド QRS ブランチの場合は最大 2 グループ。
4. グループのサイズで並べ替えます。`group 1` が主要なグループです。
5. ペーシングされたビートは、ネイティブの測定ファミリーの汚染を避けるために個別に再編成されます。

<a id="63-measurement-group-选择"></a>
### 6.3 測定グループの選択

`api.py::_select_measurement_group()` ペースビートの割合に応じて測定可能なグループを選択します。

- グローバルペースマジョリティが使用されている場合、ペースビートが優先されます。
- それ以外の場合は、ネイティブ/ノンペースビートが優先されます。
- その後の描写で、ペーシングされたグループが不安定で、安定したネイティブファミリーが存在することが判明した場合、測定グループが再選択されます。

最終結果は次のように記述されます。

- `representative_group_id`
- `measurement_beat_ids`
- `measurement_group_reselected`
- `measurement_group_reselect_reason`

<a id="7-representative-beat-构建"></a>
## 7. Representative beat ビルド

実装場所：`representative.py`

各グループ構成はビートを表します。

- ウィンドウ: `R - 300 ms` ～ `R + 500 ms`
- 相互相関アライメントにはベクトルの大きさを使用し、最大ラグ `+-30 ms`
- 不規則なリズムの場合、グループ内のビート数が `>=6` および RR CV `>0.15` の場合、グループ中央値 `+-20%` 内の RR のビートが最初に保持されます。
- 形態学ファミリーの割り当てを使用して支配的なファミリーを選択する
- medoid を使用して支配的なファミリーを表し、必要に応じて相関係数しきい値 `0.70` を使用して外れ値ビートを除外します。
- フォールバックはサンプルごとの中央値です

脈動の表現は主に次の目的で使用されます。

- 事前に P/QRS/T 境界を提供してください
- 体格測定 representative beat
- 安定した代表リードパラメータ

<a id="8-逐搏逐导联-pqrst-边界定位"></a>
## 8. ビートごとのリード P/QRS/T 境界の位置決め

実装場所: `delineate.py`、`repolarization.py`、`p_morphology.py`

<a id="81-beat-窗口和搜索范围"></a>
### 8.1 ビートウィンドウと検索範囲

各ビートのデフォルトの分析ウィンドウ:

```text
beat_start = R - 350 ms
beat_end   = R + 550 ms
```

T エンドは、次の QRS の前に保護ゾーンを通過できません。

```text
t_cap = next_R - max(150 ms, 28% * RR)
```

P 波ルックバック適応:

- 最初のビート: `400 ms`
- その他のビート: `min(450 ms, 65% * previous_RR)`

<a id="82-representative-prior-和多导联-pt-anchor"></a>
### 8.2 代表的な事前およびマルチリード P/T アンカー

representative beat がある場合、各グループ/リードの前に境界オフセットを取得するために、最初に代表的な拍動に対して大まかな描写が行われます。

拍動レベルの P/T アンカー フュージョンは、拍動間の測定中にも実行されます。

- すべてのリードから P/T ピーク候補トリプレットを収集します。
- 品質マーカーと代表的な事前分布を組み合わせます。
- P アンカー クラスターの半径は約 `12 ms` です。
- T アンカー クラスターの半径は約 `20 ms` です。
- 融合アンカーは各リードのローカル検索ウィンドウを狭めますが、すべての境界をハードカバーするわけではありません。

<a id="83-qrs-边界"></a>
### 8.3 QRS 境界

`_qrs_bounds()` のコア:

- シングルリード信号用のバンドパス `5-30 Hz`。
- 一次微分二乗エネルギーによる平滑化、`12 ms`。
- しきい値は `max(4% * QRS peak energy, 1.5 * noise_floor)` です。
- QRS 検出器が低勾配フォールバックを使用する場合、低勾配基準ガードが有効になります。
- 二次微分ゼロクロッシングを使用してオンセット/オフセットを調整します。
- 持続的な低斜面QRS足のための追加の救助。
- オンセット/オフセット、ノッチ数、オンセット/オフ信頼度を返します。

ペーシングビートの特別な処理:

- スパイクがビートに近い場合、QRS の開始をスパイクより早くすることはできません。
- キャプチャが確認され、QRS が狭すぎる場合、最小 QRS 幅 `120 ms` フロアがペースビートに適用されます。
- 固有の QRS が大幅に狭い場合、QRS エッジ アーティファクトがペーシングされた QRS と間違われるのを防ぐためにフロアが抑制されます。

QRS オフセット未加工修復の 2 番目のパス:

- 各リード×ビートの最初の QRS 測定が完了したら、まず信頼できる QRS リードを使用してビートレベル測定端末のコンセンサスを確立します。
- コンセンサスから明らかに逸脱し、オフセット信頼度が低く、マルチリードコンセンサスによって後期/早期外れ値と判断された生の `qrs.offset` については、元の `WaveBounds` の部分的なレビューと修正が許可されます。
- 修正後も安全に再計算できるリード×ビートの`qrs_ms`、QRS領域/符号領域、`j_index`、ST-J/ST40/ST80、JT/QT、端子形態を即座に再計算します。
- このパスは、QRS オンセットを変更せず、すべてのリードを同じオフセットに強制しません。幅広い QRS/BBB/ペーシング分類では、依然として `qrs_wide_ms` パスが保持されます。
- 元の QRS 幅自体が妥当であり、ST/T の混乱やビートの信頼性が低いという証拠がない場合、過度に短縮した修正は拒否されます。

ST/J raw 再測定の 2 回目のパス:

- 信頼性の高い QRS リードを使用して、QRS オフセット生修復後にビートレベルの J ポイント測定のコンセンサスを確立します。
- J ポイントと ST40/ST80 ジャンプが大きすぎる、ローカル J ポイントがコンセンサスから明らかに逸脱している、またはビートが信頼できない `st_j_unreliable` の場合は、同じリードの元の波形で ST-J/ST40/ST80 をリサンプリングします。
- `st_on_mv`、`st_mid_mv`、`st_80ms_mv`、`st_slope_mv_per_ms`、`st_morphology`の再計算を修正しました。
- このパスは、互換性のために `qrs.onset`、`qrs.offset`、または `j_index` を変更しません。実際の ST サンプル アンカーは `st_j_remeasured_index` に書き込まれ、元のインデックス、デルタ、原因、サポート リード、および除外リードがログに記録されます。
- J/ST40/ST80 が内部的に一致している場合、それは真の ST 上昇/低下である可能性があることを意味し、再検査は必要ありません。
- レポート レベルの PR/QRS/QT および LUDB フルバッチの欠落しているインジケーターは変更されず、1724 の生の ST/J リード×ビート特徴が再テストされ、164 レコードがカバーされます。

<a id="84-p-波"></a>
### 8.4P波

ネイティブ P 波パス:

- 検索ウィンドウは QRS より前にあり、融合 P アンカー以前によって制限されます。
- 候補ピークはおおよその生理学的 PR 範囲内に収まる必要があり、現在のコードではおおよそ `60-350 ms` の事前範囲検証が使用されます。
- 振幅は少なくとも `max(8 uV, 1.5% * R amplitude)` である必要があります。
- onset は昇順の接線を使用し、offset は降順の接線を使用します。
- 最終候補の再選択後、ゼロ位相 `35 Hz` ローパス P を追加生成します。
  検出ビュー。元の測定信号は、振幅、面積、形状の測定に引き続き使用されます。
- 後続の拍動は、前の拍動 T オフセットと現在の拍動 P オンセットの間の検証された TP クワイエット ウィンドウからのみ推定されます。
  ローカルノイズ。 PR/PQ セクションには Ta が含まれており、ノイズ基準としては使用されなくなりました。最初のショットは、次のように明示的にマークされている場合にのみ使用できます。
  `previous_t_out_of_context` の未検証の pre-P フォールバック。出力
  `p_local_noise_rms_mv`、`p_local_snr`、`p_informative`。 `2 sigma`未満
  候補は、信頼度の低いカバレッジのフォールバックのために保持されますが、信頼度の高い境界順序統計には参加しません。
- 出力 `p_tp_gap_ms`、`p_quiet_window_available`、`p_on_t_overlap_risk`、
  `p_ta_overlap_risk`、`p_baseline_method`、`p_baseline_confidence`。
  TP が消失すると、境界安定性診断の P 候補の両側に連続的なロバストな 2 次トレンドのみがフィッティングされます。
  元の境界は上書きされません。境界の信頼度には上限があり、マルチリード融合は強制的にクラスター中央値にフォールバックします。
- `4%-12%` 閾値摂動を伴うローパス P ビューの接線で測定
  `p_onset_sigma_ms` / `p_offset_sigma_ms`、P 波の存在の信頼性を境界の安定性から分離します。
- 長い PR により、早期の P 発症を救うことができます。
・ P/QRS の幾何関係が不合理な場合は、P を破棄するか、PR に使用できない情報のみを残します。
- P 候補コンテキストは、元の候補ごとにテンプレートの類似性、マルチリードのサポート、PR の一貫性、および PP の一貫性を計算します。短い PR 候補が同時に弱いテンプレートと PP タイミングを持ち、胸部リード/非四肢リードによってのみサポートされている場合、複数のリードが同時に誤検出されたとしても、最終 PR レポートで生の P オンセット/オフセット エラーが隠蔽されることを避けるために、ノイズのような P 候補として抑制されます。
- 代表的な P 軸は、`p_area` と `p_amp_mv` シンボルを組み合わせて符号付き P 領域を取得し、P 候補コンテキストと組み合わせて四肢誘導極性のコンセンサスを作成します。 I/II/aVF などのハイコンテキスト P 波が安定した心房ベクトルを形成する場合、QRS フロント Na/Q トラフまたはベースライン オフセットによる P 軸の逆方向への反転を避けるために、信頼性が低くコンテキストが低く、投影方向が矛盾する aVR/aVL/III 寄与波が除外されます。
- 全体的な P ベクトルが明らかに反転しているが、PR サポートが安定した正弦波のような範囲にあり、I/II/aVF/aVR が十分な反転票を与えている場合、P 軸寄与者のグループ全体が反転され、「実際の P が QRS の前の負の谷によって抑制される」という極性の問題が修正されます。複数のハイコンテキストリードによって実際にサポートされているが、洞様 PR の証拠がないネガティブ P ベクトルは、強制的に戻されません。
- P 軸には、最小限の前方サポートも必要です。四肢リードが 2 つ未満の場合、軸は報告されません。リードが 2 つしかない場合は、安定した PR サポートがなければなりません。そうでない場合は、N/A が報告されます。これにより、PR サポートなしのシングル リードまたはデュアル リード ノイズによる 180 度などの誤った軸のハード計算が回避されます。

ペースビート P 波パス:

- QRS オフセット `40-250 ms` の後の逆行 P を検索します。
- 振幅は約 `>=0.03 mV` である必要があります。
- 必要な幅: `<=120 ms`。
・QRS/Tと重複する場合は破棄します。

<a id="85-t-波和-t-end"></a>
### 8.5 T 波と T エンド

T 波検索は QRS の後に開始されます。

- ペースビート: 少なくとも QRS オフセット、その後に `40 ms` が続きます。
- 幅 QRS: QRS オフセット リア `40 ms`。
- ナロー QRS: QRS オフセット リア `20 ms`。
- 同時に、QRS テール/J 波に陥ることを避けるための R+40/R+80 ミリ秒などの保護機能があります。

`detect_t_wave()` は以下を組み合わせます:

- 予想されるリード極性、例: I、II、aVF、V5、V6 は陽性と予想されました。
- マルチリードクラスター極性。
- ST-T 混乱マーク。
- T 検索ウィンドウのベースライン交差によってセグメント化された重要なコンポーネント。コンポーネント領域が `160 uV*ms` に達した場合にのみ、T/T' 形態学的証拠とみなされます。
- 面積と幅によってサポートされる重要なコンポーネントは T ピークの選択をフィードバックし、狭い初期の ST スパイクを抑制して実際の T ピークを捕捉します。
- T ピークの後に、逆のベースラインと交差する重要な領域 T' コンポーネントがある場合、最初の T オフセットを最後の重要なコンポーネントの終わりまで拡張することができ、`t_prime_peak` が 12SL スタイルのプロファイルに渡されます。

T エンドではコード/幾何学的な方法が優先的に使用されます。

・T ピークから探索終了点まで弦を描きます。
・極方向の最大弦距離位置をT端とします。
- 低振幅または短いアームにはしきい値フォールバックを使用します。

追加の保護:

- 二相性/ノッチ T は 2 番目のコンポーネントまで拡張しようとします。
- 顕著な U 波がある場合、T 端が T-U の最下点をクリップする可能性があります。
- 事前代表者は、QT の不当な短縮を避けるために、合理的な状況下でのみ T エンドの延長を許可します。
- QT `<200 ms` の場合、T 端は破棄されます。
- グローバル QT 集約段階で、信頼できる生 QT のマルチリード クラスターが安定しており、コンセンサス QT より大幅に遅い場合、コンセンサス T エンドが時期尚早である可能性があることを意味し、アルゴリズムは遅い生 QT クラスター レスキューを使用します。これは記録に基づく特別な判断ではありませんが、通常の QRS、通常の RR、十分なリード サポート、T の可視性、および十分な T 端の信頼性が必要です。

T エンドの未加工修復の 2 番目のパス:

- 各リード×ビートの最初の T ピーク/T エンド測定が完了したら、まず信頼できる QT リードを使用してビートレベルの T エンド測定のコンセンサスを確立します。
- 一般的なコンセンサス修復の前に、より保守的なデュアルメソッドの生レスキューを実行します。明らかな早期の切り捨て、信頼性の低さ、またはフォールバック/リスクのある生の `t.offset` のみを処理し、コード、スロープ リターン、およびタンジェント スプレッド `<=30 ms` の 3 つの T エンド エンドポイントを必要とします。
- デュアル レスキューは、独立した来歴を記録します: `t_offset_dual_original_index`、`t_offset_dual_rescued_index`、`t_offset_dual_consensus_index`、`t_offset_dual_support`、`t_offset_dual_chord_index`、`t_offset_dual_slope_index`、`t_offset_dual_tangent_index`、`t_offset_dual_method_spread_ms`。
- 生の `t.offset` がコンセンサスより大幅に前または後であり、信頼性が低い、または `t_end_fallback` / `st_t_confusion` / `beat_unreliable` の証拠がある場合、同じリード信号で T エンドを再検索することが許可されます。
- `qt_ms`、`jt_ms`、`t_dur_ms`、`t_area`、`t_signed_area`、`tpe_ms`は修正後すぐに再計算してください。
- 高い信頼性と合理的なフォームを備えた本物のロン T は、強制的にコンセンサスに引き戻されることはありません。修復候補が QT `<280 ms` を引き起こすか、次の QRS ガードを越える場合、または二重法の発散が大きすぎる場合、修復は拒否されます。
- このパスは、QRS を変更せず、QT 分散/レポート比較基準も変更しません。
- T エンド デュアルメソッド raw レスキューおよび T エンド コンセンサス raw 修復は、QRS オフセット raw 修復および ST/J raw 再測定の後、最終的な `_apply_multilead_consensus()` の前に実行されます。

<a id="102-global-hr-和-pr"></a>
### 10.2 グローバル人事および広報

HR は R-R 中央値を使用します。

```text
HR = 60000 / median(RR_ms)
```

PR 代表的なリードからの最初のグローバル PR 中央値。 AF/AFL や P サポートが不十分など、心房測定が無効な場合は、空白のままにすることができます。

`api.py` および生理学的 PR コアレスキュー:

- ビートごとの PR から核となる価値を抽出します。
- リズムが許可され、QRS が狭く、RR ルールがあり、PR コアが `120-240 ms` にある場合、明らかに異常または欠落しているグローバル PR は置き換えられます。

<a id="103-global-qrs"></a>
### 10.3 グローバル QRS

グローバル QRS はコンセンサス測定 QRS から優先されます。

- 測定用 `qrs_consensus_ms`
- 幅広い分類は `qrs_wide_ms` を参照できます
- ペーシングまたはペーシングに似たコンテキストで生/コンセンサスが一貫していない場合、`api.py` は複数の QRS オーバーライド パスを適用して、ペーシングまたはワイド QRS が ST/T テールによって過小評価されたり、過度に拡張されたりするのを防ぎます。

<a id="104-global-qt-和-qtc"></a>
### 10.4 グローバル QT および QTc

QT は、現在の実装で最も複雑な集約パスです。

信頼できる QT リードには次のものが必要です。

- `reliable_for_qt`
- T 波が表示されます、デフォルト `|T_amp| >= 0.05 mV`
- QT ビートツービート SD `<25 ms`
- T エンドの信頼度 `>0.20`
- QTは生理的範囲内です

厳密なパスにリードがない場合、レスキュー パスによって最適なリードが選択されます。

- QT SD `<30 ms`
- 自信 `>0.10`

ペーシング中のワイド QRS/QT パス JT 合理性の使用:

```text
JT = QT - QRS
允许范围约 160-550 ms
```

QT 集約の優先順位はおおよそ次のとおりです。

1. 信頼できるリードのコンセンサス QT 中央値。
2. ワイド QRS 生の QT レスキュー。
3. raw QT コアのレスキュー。
4. 信頼性の高い生の QT クラスターのレスキュー。
5. 遅い生 QT クラスターのレスキュー: 通常の QRS/通常のコンセンサス RR では、安定した生の QT クラスターが QT より少なくとも約 `20 ms` 遅い場合、生のクラスターを使用して短い QT 外れ値を防ぎます。
6. 分割生 QT レスキュー。
7. 信頼できるリードの振幅加重中央値。
8. グローバルで信頼性の高いリードフォールバック。
9. 変則ビートQTコア。
10. raw QT 後期コアレスキュー。
11. 優先リードフォールバック: `II, V5, V4, V6, III, aVF`。
12. 低サポートの遅延生 QT クラスターのレスキュー: `low_qt_support` パスでは短い QT しか得られないが、狭い QRS、RR ルール、および複数の信頼できる/グローバル リード生 QT がタイトな遅延クラスターを形成する場合、生クラスターを使用してグローバル QT を修正します。このパスは各リードの生の QT を書き戻さないため、QT の分散を強制的に平坦化することはありません。

QT パスの決定により以下がマークされます。

- `normal_qrs`
- `wide_qrs_jt`
- `paced_jt`
- `low_qt_support`

最終出力:

- `qt_ms`
- `qtc_bazett_ms = QT / sqrt(RR_sec)`
- `qtc_fridericia_ms = QT / cbrt(RR_sec)`
- `qt_dispersion_ms`
- `qt_source`
- `qt_used_leads`
- `qt_reliability`
- `qt_path`
- リードごとのコンセンサスと独立した比較

`qt_reliability == low_confidence` または信頼できる QT リードがない場合、解釈層は QTc 延長解釈を禁止します。

<a id="105-axis"></a>
### 10.5軸

前頭軸は、6 つの四肢誘導の符号付き面積または振幅推定値を使用します。

- P 軸: P 符号付き面積/P 振幅、P は信頼できることが必要です。
- QRS 軸: QRS ネット面積/振幅。必要に応じて、ピークネットまたは初期コア QRS 軸で補正できます。
- T 軸: T 符号付きエリア/アンプ、ST 補正、クラスター、サプレッション、フォールバックによる多層化。
- ST 軸: ST 中間値。

T 軸の追加保護:

- 幅 QRS、ペーシング、T 振幅が低すぎる、極性の競合、ST-T の混乱、明らかな異常がある場合、RR は空白のままになる場合があります。
- I/II/aVF が強力で同方向の四肢シード T コンセンサスを形成する場合、シード投影と明らかに矛盾し、十分な信頼性サポートに欠ける aVR/aVL/III の値は、単一四肢誘導極性の誤検出と T 軸の偏りを避けるために除外されます。
- ST 補正された T 軸は、十分な ST 信頼度を持つ ST サンプルのみを使用します。 QRS オフセットの信頼性、QRS オフセット修復または ST サンプルが不安定な場合、STJ/STM/STE は出力されますが、T 軸を支配しません。
- QT サポートが低いために通常の T 軸が抑制されるが、QRS が狭く、RR ルールで、複数の四肢誘導に安定した T 振幅/符号付き領域があり、軸が極端ではない場合、低サポート T 軸カバレッジ フォールバックを使用できます。 12SL スタイルのプロファイルが STJ/STM/STE、特別な T および ST 信頼性を書き戻した後、API レイヤーは狭い範囲の T 軸バックフィルも実行し、元の N/A の安定した低サポート T 軸のみを埋めます。このフォールバック/バックフィルは、「形態学的証拠は安定しているが、QT 信頼ゲートが保守的すぎる」レコードのみを復元し、広い QRS/ST プラトーまたは低振幅の不安定な T には使用されません。
- `t_axis_reliable` には、少なくとも 2 つの四肢リード `|T_amp| > 0.15 mV` が必要です。

LUDB 比較の軸の要約では、符号付き生の差分と循環絶対差分の両方が保持されます。

- `diff_p_axis/diff_qrs_axis/diff_t_axis` は依然としてアルゴリズムの直接の違い - 方向性を確認するためのグラウンド トゥルースです。
- `abs_p_axis_circular_diff/abs_qrs_axis_circular_diff/abs_t_axis_circular_diff` は、`176°` と `-175°` が `351°+` として誤って計算されるという大きな間違いを避けるために、円の角度の差を使用します。

<a id="11-atrialafafl-和-rhythm-availability"></a>
## 11. 心房、AF/AFL およびリズムの可用性

実装場所: `atrial.py`、`rhythm_rules.py`、`api.py`

<a id="111-atrial-event-extraction"></a>
### 11.1 心房イベントの抽出

`extract_atrial_events()` ソースには次のものが含まれます。

- リードごとの P ピーク、`p_confidence >=0.30` およびリード `reliable_for_p` が必要です。
- 心拍間心房スキャン。
- 生の ECG が利用可能な場合は、複合生の P 検出を優先します。それ以外の場合は、リードごとの粗いスキャンにフォールバックします。

候補は時間によってクラスター化され、重複が排除され、最も近い QRS に関連付けられます。

- `conducted`
- `blocked`
- `retrograde`
- `unknown`

<a id="112-qrst-residual-与-afafl"></a>
### 11.2 QRST 残差と AF/AFL

`build_qrst_subtracted_residual()` は QRST ウィンドウ残差の概要を構築します。

- 最初にテンプレート減算を試みますが、これは AF/AFL 残差のみを提供し、考慮されません
  P-on-T のユニバーサル ソリューション。 QRS は R を整列させます。 ST-T はビートごとの微分相関によって変換され、
  Huber スタイルの反復的に再重み付けされたフィット振幅/バイアス。 QRS→ST-T で、テンプレート ウィンドウの両端でコサイン勾配を使用します。
- テンプレート相関 `>=0.85` のみ、ビート数は十分であり、残留 RMS 比は適格です。
  また、2 次微分高周波エネルギー比が `<=1.25` の場合にのみ、検証済み QRST subtraction とマークされます。
- 中央値RRが`<520 ms`の場合、テンプレートサポートウィンドウが次のPエリアに侵入する可能性があり、連続QRST
  残りのパスは直接利用できません。
- それ以外の場合、スキャフォールドの概要は引き続きルール入力用に公開されます。

`_classify_af_afl()`：

・RR CV `>=0.15`、組織Pレシオ `<0.25`、残留繰り返しが強くない場合はAFになりやすい。
- フラッターは、残留ドミナント サイクル `120-400 ms` とスペクトル証拠を使用します。
- フラッター信頼度 `>=0.60` のときにフラッターの可能性をマークし、同時に AF を判断しないようにします。

<a id="113-rhythm-rules"></a>
### 11.3 リズムルール

`rhythm_rules.py` は以下を提供します:

- ペーシングの状況: 連続/断続/心室/心房/二腔ペーシング。
- ペーシング失敗: スパイク後の `160 ms` に QRS がない場合、キャプチャ失敗の疑いがあります。
- 予励磁/WPW: 短い PR、短い PR セグメント、デルタリード、QRS `>=100 ms`、初期 QRS 軸。
- 一時停止と二次 AV ブロック: RR 一時停止、RR ごとの心房イベント、PR シリーズ。
- 一時停止後のエスケープ/補間されたビート候補。
- 測定の可用性。

<a id="114-measurement-availability"></a>
### 11.4 測定の可用性

次のシナリオでは、心房調律、PR、P 軸、およびその他の測定値が下流の調律解釈に適さなくなります。

-継続的なペーシング
- 幅広い QRS ペーシングのようなコンテキスト
-AFの可能性あり
-フラッターの可能性
- 完全な AV ブロック
- AV解離
- 心房測定は利用できません

`api.py::_apply_measurement_availability_to_representatives()` は、可用性が非常に低い状況では、グローバル PR フィールドと代表 PR フィールドを空白のままにします。

<a id="12-12sl-style-并行-measurement-profile"></a>
## 12. 12SL スタイルの平行測定プロファイル

実装場所: `twelve_sl.py`

このモジュールは、ネイティブの DXL スタイルのメイン測定を直接カバーしない並列プロファイルを生成します。

ビート/リードごとに計算:

- STJ、STM、STE
- STM オフセット = RR / 16
- STE オフセット = RR / 8
- ST/T 振幅基準 = QRS 開始電圧
- QRSエリア、サインエリア、バランス、リフレクション
-最小ST
- T/T': T' は、T ピーク後の有意なベースライン交差成分から推定され、有意領域のしきい値は `160 uV*ms` です。
- ST 信頼度: 低い QRS オフセット信頼度、QRS オフセット修復、STJ/STM/STE の不安定性、または ST サンプルの欠落により、`twelve_sl_st_confidence` が減少し、`twelve_sl_st_confidence_reason` を記録します。
- 特別な T 振幅: 基本ルールは `min(T, T - STE)` です。ただし、ST 信頼性が低い場合、ST テール/QRS オフセット エラーによる T 形態の汚染を避けるために、STE は特殊な T 分岐に参加しません。有意な負の T' は特殊な T をオーバーライドします。小さな負の T' は、正の T がその 4 倍以上であり、`|T'| < 70 uV` の場合には無視されます。負の T が存在し、T' が存在しない場合にも、T オフセット電圧ブランチが比較されます。
- QRS 重要度、しきい値 `160 uV*ms`

レコードレベルのプロファイルには次のものが含まれます。

- 最初から最後の QRS 心拍数
- マルチリードグローバル基準: R に対する P/QRS/T オフセット中央値サマリー
- 定数とプロファイルのバージョン

エクスポート レイヤーには、次の 3 セットの測定プロファイルが提供されます。

- `native`
- `12sl`
- `hybrid`

ハイブリッド戦略では、グローバル軸と QT 分散はネイティブのままで、ST/QRS/T プロファイル値が 12SL の使用可能な値よりも優先されます。

<a id="13-clinical-interpretation-层"></a>
## 13. 臨床解釈層

実装場所: `interpret.py`、`mi.py`、`pediatric_rules.py`、`statement_engine.py`

解釈層は元の波形を再処理しませんが、次のものを消費します。

- `global_features`
- `representative_leads`
- `beats`
- `beat_features`
- `metadata["rhythm_analysis"]`

<a id="131-判读流程"></a>
### 13.1 解釈プロセス

コードは、臨床カルテの読み取りと同様に階層的に編成されています。

1.技術的な品質とリードの逆接続。
2. リズムとレート。
3. 軸と間隔。
4. P/QRS/T/ST 形態。
5. 解剖学的位置、MI、肥大、相互変化。

<a id="132-rhythmrate"></a>
### 13.2 リズム/レート

- HR `<45 bpm`: `extreme_bradycardia`
- HR `<50 bpm`: `bradycardia`
- HR `<100 bpm`: `normal`
- HR `>=100 bpm`: `tachycardia`
- RR CV `>0.15`: `irregular`
- RR CV `>0.08`: `mildly_irregular`
- 不規則で P 信頼度が低い場合は AF の可能性があります。

<a id="133-axisconductionqtc"></a>
### 13.3軸/通電/QTc

- QRS 軸: 通常の `[-30, 90]`、LAD/LAFB/RAD/LPFB/ERAD 階層化。
・T軸：ノーマル`[-10, 100]`。
- PR: 短い `<120 ms`;年齢および HR 動的テーブルを使用した 1 度 AVB しきい値。
- QRS:
  - `<100 ms`: 通常
  - `100-110 ms`: IVCD 境界線
  - `110-120 ms`: 非特異的 IVCD
  - `>=120 ms`: BBB/IVCD、および V1 R'、横 S、V1/V6/I 振幅に基づいて RBBB/LBBB を判断します。
- QTc:
  - `<340 ms`: 短い
  - `>465 ms`: 境界線が長期化
  - `>485 ms`: 長期化
  - `>520 ms`: 大幅に延長
  - BBB、RVH/LVH などは、QTc 延長ステートメントを禁止できます。

<a id="134-morphology-和解剖定位"></a>
### 13.4 形態と解剖学的位置

解釈層の範囲:

- WPW/予励磁
- RAE/LAE/BAE（P 持続時間、P 振幅、V1 終端成分、PTF-V1 を含む）
- 病理学的 Q 波と領域: 下/前/外側
- R波の進行とR/S移行
- ST上昇/低下領域、STEMIスタイルコード、相互変化
- Cornell/Sokolow/aVL などを含む LVH 電圧/スコア
- 低電圧
- RVH 採点スコア
- 背の高いT
- 右心筋症
- COPDのパターン
- 後部MIと原因となる動脈の証拠
- ステートメント候補と抑制/バイパス

LBBB は二次再分極に関連する判断を抑制します。

- ST上昇/低下
-T波異常
- Q波梗塞の兆候
- 相互の変化

<a id="135-儿童规则"></a>
### 13.5 子供のルール

年齢 `0 <= age < 16` で小児形態ルートを選択します。

- 子 QRS 軸と QRS 期間は年齢ビニングしきい値を使用します。
- 小児 QTc 閾値は年齢と性別によって異なります。
- RVH/LVH/LSH/BVH は、`pediatric_rules.py` の年齢ビン電圧しきい値を使用します。
- RBBB/LBBB は肥大解釈の一部をバイパスできます。
- 特定の年齢範囲内での心膜炎と早期再分極の管理。

<a id="16-关键设计约束和已知限制"></a>
## 16. 主要な設計上の制約と既知の制限

1. このプロジェクトは、DXL からインスピレーションを得た研究足場であり、規制当局によって検証された診断ソフトウェアではありません。
2. 品質、ペーシング、AF/AFL、幅 QRS、LBBB、およびその他のシナリオでは複数の抑制/レスキューがトリガーされるため、単一の生の間隔だけを確認することはできません。
3. `beat_features` はビートバイリードの元の測定パースペクティブ、`representative_leads` は測定グループのサマリー、`global_features` は下流解釈のためのグローバル集計パースペクティブです。
4. 12SL プロファイルは平行出力面であり、ネイティブ測定を置き換えることと同等ではありません。
5. QRST subtraction は、テンプレートの検証を満たした場合にのみ検証されます。それ以外の場合、それは単なる足場残余の要約です。
6. ペーシングビートの専用の説明は、まだエンジニアリングの実装と保護ロジックであり、複雑なペーシングタイプについては、さらに検証が必要です。
7. 子供の閾値は年齢/性別によって異なります。年齢が不足している場合や違法な場合は、デフォルトで成人向けルートが設定されます。
8. リード反転の検出は、軸、前胸部進行および解釈に影響を与えるヒューリスティックですが、最終的な医学的確認ではありません。
