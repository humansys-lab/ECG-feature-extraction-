# Project Code and File Organization Report

Organization date: 2026-08-19

## 1. Outcome

This cleanup removed an obsolete test scratch file, caches, logs, runtime manifests, and reproducible experiment outputs without changing ECG algorithms or Agent business logic. Workspace usage decreased from about 137 GB to about 125 GB, reclaiming roughly 12 GB.

The formal tests, raw datasets, local models, external references, and current Python virtual environment were retained. The complete test run finished with 1515 passed, 2 intentionally skipped, and 150 subtests passed.

The missing local link required by the demo entry point, `dataset -> data/010`, was restored and verified against example `.hea` and `.mat` files.

## 2. Removed Content

| Category | Removed content | Reason | Recovery |
|---|---|---|---|
| Historical test scratch | `tests/_multilead_pt_scratch.py` | Its name was not collected by pytest, while formal coverage already exists in `tests/test_multilead_pt_fusion.py` and related tests | Recoverable from Git history |
| Python caches | Project `__pycache__/`, `.pytest_cache/`, `*.pyc`, and `*.egg-info/` files | Automatically generated by Python, pytest, or installation | Recreated by running or installing the project |
| Runtime intermediates | `.doc_translation_cache.json`, two manifests, Web UI uploads, and logs | Ignored by `.gitignore` and not source code | Recreated by the corresponding commands |
| Validation and plot artifacts | `ecgfeat_validation_20260811/`, `ludb_delineation_plots/`, and `p_wave_failure_plots/` | Reproducible from validation and plotting scripts | Re-run the corresponding scripts |
| Feature and inference outputs | `ptbxl_09000_ecgfeat/`, `qwen_agent_output/`, and `deepseek_v4pro_05490_v12/` | Derived features, diagnoses, or experiment output rather than input data or source | Rebuild from the retained data, models, and scripts |

The ignored generated artifacts had no Git versions, so Git cannot directly restore them after deletion; an external backup can also be used if one exists.

## 3. Retained Content and Directory Responsibilities

```text
ecg_gemma/
├── feature_extraction/ecgfeat/  # reusable ECG feature extraction library
├── ecgagent/                    # diagnostic agent and evidence pipeline
├── webchat/                     # web UI and model server
├── scripts/                     # maintenance, localization, and cohort utilities
├── tools/generation_conditions/ # focused audit and probe tools
├── tests/                       # unit, contract, and regression tests
├── docs/                        # design, algorithm, and validation documents
├── dataset -> data/010          # default demo dataset link (ignored)
├── data/                        # local raw/reference datasets (ignored)
├── medgemma-27b/                # local model (ignored)
├── qwen3.8-27b/                 # local model (ignored)
├── document/                    # external reference material (ignored)
├── *.py                         # compatible command-line entry points
└── requirements*.txt            # dependency definitions
```

| Area | Retention reason and maintenance boundary |
|---|---|
| `feature_extraction/ecgfeat/` | Core ECG measurement, quality, rule, and export implementation; reusable algorithms belong here |
| `ecgagent/` | LLM backends, diagnostic flow, evidence, tools, verification, and reports; it does not perform low-level ECG measurement |
| `tests/` | Source of 1517 formal tests; tests are regression protection and are not treated as temporary files |
| `docs/` | Algorithm design, validation conclusions, and maintenance records; Markdown extensions are now consistent |
| `data/`, model directories, `document/` | Large but necessary inputs or references, retained locally and isolated by `.gitignore` |
| Root Python files | Existing CLI, demo, evaluation, and plotting entry points; direct imports exist in multiple places, so they remain in place for command and test compatibility |

Root entry points are grouped by purpose: UI and demos (`app.py`, `demo_feature_extraction.py`, `visualize_ecg.py`); extraction and runtime (`batch_extract_ecgfeat.py`, `medgemma_ecg_core.py`, `medgemma_runtime.py`); Agent/model batches (`run_*.py`, `batch_medgemma_diagnostics.py`); dataset evaluation and validation (`evaluate_*.py`, `validate_*.py`, `compare_*.py`); and result analysis and visualization (`analyze_*.py`, `ludb_*analysis.py`, `plot_*.py`, `render_*.py`).

## 4. Documentation Filename Normalization

Six formal documents without extensions now have explicit Markdown names: `P波文档.md`, `QRS.md`, `Twave related.md`, `morphological.md`, `p wave doc.md`, and `流程.md`. Their Chinese, English, and Japanese navigation and body references were updated together.

The localization script was also fixed: it now ignores stale index paths that no longer exist and checks new non-ignored documents, allowing renames and additions to be validated before Git staging.

## 5. Ongoing Maintenance Rules

- Python/pytest caches, logs, uploads, and clearly derived outputs inside the project can be cleaned at any time; do not run an unscoped cleanup command over the entire repository.
- `data/`, `medgemma-27b/`, `qwen3.8-27b/`, `document/`, and `.venv/` are not treated as intermediates and require separate confirmation before deletion.
- Formal tests use the `tests/test_*.py` pattern; one-off probes belong in `tools/` and should not remain in `tests/` as uncollected underscore-prefixed files.
- New reusable logic belongs in `ecgfeat` or `ecgagent`; root entry points should retain only argument parsing, task orchestration, and output writing.
- New large result directories should be added to `.gitignore` and should use clear output directory names in their commands.

## 7. High-Risk Refactoring Not Performed

This cleanup did not force more than 40 root CLI scripts into nested directories. The scripts and tests contain direct module imports, so a move would change public commands and Python import paths. A future root reduction should be a separate entry-point migration with compatibility wrappers, documentation updates, and a complete regression run.
